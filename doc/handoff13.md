### 64~66은 노트였고 **67이 코드다**

「64~66 노트만 있고 코드는 없었다. 이번에 넣었다.」

> **인계문 12의 7번이 한때 「코드가 없다」였던 이유가 여기다.** 노트가 먼저 있었고
> 코드가 뒤에 왔다. 그 표는 **`1145e58`에 사실로 고쳤다.**

### 코드에서 확인한 것

| 무엇이 | 어디 |
|---|---|
| `REFRI_SCENE_MAX_H = screenHeight × refriSceneHeightRatio` — **상한**을 상수로 | `refri-test/index.tsx:25` |
| 냉장고 칸이 **고정 40% → `flex: 1` + `maxHeight`** (`minHeight: 0` · `width: '100%'`) | `styles.refriContainer` |

## 세션 68 — learn 진행 게이지 · 문서 셋 · **한 작업 트리에 작업 둘**

**게이지 코드는 사용자가 다른 창에서 썼다.** 이 창이 한 것은 **설계 문서 머리 둘**과
**커밋을 둘로 가른 것**, 그리고 점검 커밋 해시 둘을 옮긴 것이다.

### 이 세션이 실제로 한 일

| 무엇 | 어디 |
|---|---|
| `learn-액션줄.md`·`learn-그만하기.md` 머리 「미구현」 → **구현됨 + 코드 위치** | 본문은 그대로 |
| 인계문 13의 **5번을 사실로** — 틀린 짝, 「넷 다 미커밋」 | 아래 5번 |
| 냉장고 묶음 커밋 → **`b739b4b`**, 점검 커밋 `406cbb2` → 그리로 (**`d2668c1`**) | 1번이 시킨 것 |
| learn 묶음 커밋 → **`123a389`**, 점검 커밋 `73d34f6` → 그리로 (**`f81c0cd`**) | |

### 파일이 섞여서 **헝크로 갈랐다**

사용자 지시는 「**커밋을 둘로 — 냉장고 / learn**」이었는데, 그 사이 다른 창이
`constants/layout.ts` · `doc/점검-이력.md` · `doc/점검표.md` **셋에 양쪽을 다 써 넣었다.**
`learnGauge*`가 refri 주석과 한 파일에, 세션 64~67 노트와 68 노트가 한 파일에 있었다.

> **그래서 파일 단위로는 못 나눈다.** `git add <파일>`은 그 파일 전부를 담는다
> (63의 `f535e60`이 그랬다). **`git apply --cached`가 아니라 「그 커밋에 들어갈 내용」을
> 만들어 `git hash-object -w` → `git update-index --cacheinfo`로 색인에만 넣었다** —
> **작업 트리를 건드리지 않는 길**이라, 다른 창이 계속 쓰고 있어도 그 편집을 덮지 않는다.

**손으로 정한 것 하나** — 「한눈에」 합계(15,102 / 54)는 냉장고 커밋에 그 값으로 넣었다.
합계는 양쪽이 함께 만든 수라 갈라지지 않는다. **67 노트가 스스로 적어 둔 수**를 썼다.

## 화면 부위를 부르는 이름 — **원문은 [`handoff5.md`](./handoff5.md)**

flashcards·드럼·게임 넷의 이름표는 handoff5와 [`handoff12.md`](./handoff12.md)가 갖는다.
**익힘모달 ≠ 미션모달 ≠ 이름모달**, 게임 넷의 **「나가기」**(`_layout`이 그린다) ≠ 결과창 **「홈으로」**,
learn의 **액션줄**(왼쪽 토글 + 「그만하기」).

**냉장고(`refri-test`)가 세션 67에 하나 늘었다** — 게이지 · **냉장고 칸**(`refriContainer`,
`flex: 1` + 상한) · 그 안의 **씬**(배경·냉장고·상자를 한 배율로 줄이는 `refriWithCratesWrapper`) ·
**선반**(`answersContainer`, 아래를 88 비운다) · 그 칸 안의 **다시 듣기** · **시작 버튼** · 완료 오버레이.

> **「칸」과 「씬」은 다른 것이다.** 칸은 남은 높이를 받는 상자이고, 씬은 그 안에서
> **설계 크기 그대로 그려진 뒤 배율로 줄어드는** 그림이다. 칸만 줄이면 그림이 잘린다(65가 그 자리).

### 세션 64~67 주의사항 (냉장고 짧은 폰 세로)

- **칸을 줄이는 것과 그림을 줄이는 것은 다르다.** 64는 칸만 줄여 **그림이 잘릴 수 있었고**,
  65는 늘 맞춰 **확인 기기까지 줄였다.** 답은 66~67의 「**상한이면 배율 1, 짧을 때만 contain**」이다.
  세 번 고친 기록이 이력의 64·65·66이다 — **방향을 바꿀 때마다 노트를 남기면 왜 지금 모양인지가 남는다.**
- **줄어드는 쪽을 하나로 정한다.** 게이지·선반은 `flexShrink: 0`이고 **냉장고만 `flex: 1`**이다.
  안 정하면 RN 기본값대로 **셋이 같이 줄어** 어디가 얼마나 줄지 아무도 모른다.
- **`flex: 1`에는 `minHeight: 0`을 함께 준다.** 안 그러면 자식의 내용 높이가 하한이 돼
  칸이 줄지 않는다 — 63의 「남는 높이가 마지막 자식 아래에 남는다」와 짝이다.
- **실측(`onLayout`)은 한 프레임 늦다.** `sceneSlotH` 초기값이 상한이라 **첫 프레임은 배율 1**이다.
  67 재점검이 그것을 잡아 0-2절로 보냈다 — 실측으로 크기를 정하는 자리마다 **첫 프레임**을 본다.
- **인계문에 「없다」를 적을 때는 그 시점임을 밝힌다.** 이력 노트(64~66)가 코드보다 먼저 있었고,
  「코드가 없다」고 적은 뒤 **다른 창에서 들어왔다**(`3b14c88` → `1145e58`).

### 세션 68 주의사항 (한 작업 트리에 창이 둘)

- **다른 창은 「있을 수 있다」가 아니라 「지금 쓰고 있다」이다.** 세션 68이 시작할 때
  `git status`에 없던 `learn/index.tsx`가 178줄로 나타났고, **다음 확인에 183줄이었다.**
  `layout.ts`도 처음 볼 때는 refri뿐이었는데 나중에 `learnGauge*`가 들어와 있었다.
  **읽은 뒤 시간이 지나면 다시 읽는다** — 특히 커밋 직전에.
- **진행 중인 파일에 줄 번호를 적지 않는다.** 설계 문서에 `:413`·`:141`처럼 박았다가
  같은 세션 안에서 낡았다. **이름(`styles.actionRow` · `const leftAction`)으로 가리킨다.**
  움직이지 않는 파일(`WordGame.tsx`)에는 번호를 남겨 두었다.
- **작업 트리를 건드리지 않고 커밋을 가르는 길이 있다.** `git hash-object -w --path <경로> <파일>`
  → `git update-index --cacheinfo 100644,<sha>,<경로>`. 색인에만 넣으므로 **다른 창의 편집을
  덮지 않는다.** `git add -p`는 대화형이라 여기서 쓸 수 없다.
- **가른 결과는 반드시 되읽는다.** 만든 판을 `git show HEAD:<경로>`와 `git diff --no-index
  --ignore-cr-at-eol`로 대조해 **저쪽 몫이 새지 않았는지** 봤다. 이 저장소는 `core.autocrlf=true`라
  **`--ignore-cr-at-eol` 없이는 전부 바뀐 것처럼 보인다.**
- **합계처럼 양쪽이 함께 만든 수는 갈라지지 않는다.** 어느 커밋에 어떤 값으로 넣을지
  **정해서 적어 둔다** — 68은 「한눈에」를 67 노트가 스스로 적은 15,102로 두었다.
- **점검 커밋 해시는 코드 커밋 **직후에** 옮긴다.** 64·65·67 노트가 세 번 「뒤에 옮긴다」로
  남아 세 세션을 건너왔다. 68에 둘 다 옮겼다(`d2668c1` · `f81c0cd`).
- **다른 창에는 말을 걸 수 없었다.** `ListAgents`에 열 세션이 잡혔지만 **전부 `offline`**이라
  「둘로 커밋해 달라」를 전하지 못했다. **같은 작업 트리를 쓰는 창이라도 통로는 없다** —
  사용자가 옮겨 주거나, 이쪽에서 갈라 담는 수밖에 없다.

### 세션 69~70 주의사항 (작업이 둘이 아니라 셋이었다)

- **「창이 둘」이 아니라 「작업이 몇 개냐」를 센다.** 이 창이 본 것은 69 둘뿐이었고
  **기타 −1(70)은 같은 트리에 이미 들어와 있었다.** 저쪽 창은 70을 모른다 —
  둘로 갈랐으면 기타가 69에 섞였다. **가르기 전에 `git status`를 다시 읽는다**
  (68의 「읽은 뒤 시간이 지나면 다시 읽는다」가 이번엔 **작업 개수**에서 걸렸다).
- **합계도 갈라진다 — 사슬로 적으면.** 68은 「한눈에」를 「양쪽이 함께 만든 수라
  갈라지지 않는다」고 한 커밋에 몰아넣었다. 이번엔 **15,277 → 15,283 → 15,284 → 15,296**으로
  커밋마다 자기 몫만 더해 **세 판이 각자 안에서 맞는다.** 노트에도 그 사슬을 적었다.
- **가른 판이 맞는지는 「마지막 판 == 작업 트리」로 증명한다.** A→B→C를 차례로 만들고
  **C가 작업 트리와 한 글자도 다르지 않은지** 본다. 다르면 어느 몫이 새거나 빠진 것이다.
  68은 `git diff --no-index --ignore-cr-at-eol`로 저쪽 몫만 봤는데, **끝을 맞추는 쪽이 더 세다.**
- **표의 「부분」은 「한눈에」의 「부분만 훑음 0」과 한 몸이다.** 재점검은 「전수」를 유지하고
  「바뀐 줄만 봤다」는 **노트가 갖는다** — `matchGame`(59) · `matchGameAI`(69)가 그 예다.
  69가 `WordGame`을 「부분」으로 내렸다가 되돌렸다.
- **줄 수는 고친 파일을 빠짐없이 센다.** 69가 `matchGameAI` +1만 세고 `WordGame` +6을 빠뜨렸고,
  70이 그 위에 기타 +12를 얹어 **15,290**이 됐다. 맞는 값은 **15,296**이다.
- **「(미커밋)」은 표가 아니라 노트가 갖는다.** 70이 점검 커밋 칸에 `a57c217` (미커밋)이라고
  적었는데, 그 칸의 뜻은 「그 점검이 **본 상태**」다. 커밋되면 사라질 말은 노트에 둔다.
- **`ListAgents`는 이번에도 열 세션 전부 `offline`이었다** — 68과 같다. 통로는 아직 없다.
