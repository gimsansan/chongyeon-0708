### 0. 인계문을 handoff3으로 옮겼다

### 1. 내가 방향을 잘못 말했다 — 그리고 그게 설계를 바꿨다

디자인 제안에서 "드럼 탭은 회전하니 가로에서 버튼이 잘린다"고 했는데 **틀렸다.**
`app.json`의 `"orientation": "default"`만 보고 판단한 것이다.

실제 방향은 `app/(tabs)/_layout.tsx:57`의 `LANDSCAPE_ROUTES = ['/activity', '/guitar']`가
정한다. `useOrientationForRoute()`가 경로마다 `lockAsync()`를 다시 걸어서, 목록에 있으면 가로,
**나머지는 전부 `PORTRAIT_UP`**이다. 드럼도 learn도 목록에 없다.

> **`app.json`은 출고 설정이고 `_layout.tsx`는 실행 중 명령이다. 나중에 말한 쪽이 이긴다.**
> 방향을 확인할 때 `app.json`만 보면 안 된다.

그래서 제안했던 「가로에서 버튼 잘림」 대응은 **넣지 않았다.** 일어날 수 없는 상황이고,
안 쓰는 가로 분기만 코드에 남는다.

### 2. 결과 화면 (`7d2c55f`)

**전제 하나**: `DrumGameOverScreen`은 이름과 달리 **드럼과 learn 둘이 함께 쓴다**
(`learn/index.tsx`). 그런데 배경이 정반대다 — 드럼은 검은 스크림 위, learn은 밝은 `#F0F2F5` 위.
지금 스타일은 사실상 드럼만 보고 잡혀 있었다.

| 고친 것 | 왜 |
|---|---|
| 게이지가 **실측한 카드 폭**을 따라간다 | `220×40` 고정이라 카드가 `width: '100%'`로 넓어지는 태블릿에서 게이지만 남았다. 폰 240 / 태블릿 340 상한 · 원본 비율 유지 |
| 첫 프레임은 **하한(160)**으로 | 크게 어림잡으면 폭이 좁은 learn에서 한 프레임 동안 게이지가 카드 밖으로 나간다 |
| 카드·버튼줄 `maxWidth` (폰 400 / 태블릿 520) | 카드에 상한이 없어 태블릿에서 끝없이 퍼졌다 |
| 폰트·버튼 높이 `LAYOUT.isTablet` 분기 | **폰 값은 그대로 두고 태블릿만 키웠다** — 기존 화면이 안 바뀌게 |
| 등급표 `RESULT_TIERS` 하나로 | 메시지와 색이 나뉘어 있으면 한쪽만 고쳐져 어긋난다 |
| 결과를 **색으로** 가른다 | 셋 다 초록이라 「아쉬워요」도 버튼과 같은 색이었다. 세션 28 원칙(밝기 아닌 색상)대로 완벽 `#B8860B` / 잘함 `#4E9A51` / 아쉬움 `#6B7280` |

| 「나가기」를 아웃라인으로 | 두 버튼이 같은 초록 채움이라 주 동작과 구분이 없었다. 접근성 속성도 없었다 |
| 하늘색 `textShadow` 제거 | 글자는 초록인데 그림자만 하늘색이었다 — 다른 팔레트의 잔재 |

**색을 한 톤씩 내린 이유**: 셋 다 흰 카드 위에 올라간다. 금 `#FFD700`과 브랜드 초록 `#7cbd7e`는
흰 배경에서 **2.2:1**이라 큰 글씨 기준(3:1)에 못 미친다. **버튼 배경·테두리의 브랜드 초록은
그대로 뒀다** — 글자로 쓸 때만 `GREEN_ON_WHITE`(`#4E9A51`)를 쓴다.

**범위 밖인데 딸려온 것**: 메시지를 등급표로 옮기며 선행 공백(`" 완벽해요!"`)이 없어졌다.
나머지 3순위(0/0이면 「완벽해요!」 · 위계 · 숫자 카운트업)는 **그대로 뒀다.**

### 3. learn을 드럼과 같은 방식으로 (같은 커밋)

learn은 결과를 **페이지 안에** 끼워 넣고 있었다(`gameContentInner`, 위 정렬, 스크림 없음).
드럼과 같은 전체 오버레이(`gameOverOverlay`, 검은 스크림 `rgba(0,0,0,0.7)`, 중앙)로 바꿨다.

**`WordGame`은 그대로 언마운트한다.** 오버레이로 덮기만 하고 뒤에 살려두면 오디오·타이머가
남는다 — 세션 20~27에 잡았던 그 계열의 문제다. `{isGameOver ? 결과 : 게임}`을
`{!isGameOver && 게임}` + 별도 오버레이로 나눈 이유가 이것이다.

`npx tsc --noEmit` 새 오류 0건. 남은 `hooks/useSyncGameData.ts(44,51)`은 세션 29에서
무관한 기존 항목으로 확인된 것이다.

### 4. iOS 전용 코드를 걷어냈다 — 규칙 4 신설

사용자가 알려줬다. **이 앱은 안드로이드 모바일 앱이고 iOS 대응을 하지 않는다.**

바로 위 2번에서 내가 **"`elevation`은 안드로이드 전용이라 iOS엔 그림자가 없다"**는 이유로
`shadow*` 네 줄을 **새로 넣은 참이었다.** 대상이 아닌 플랫폼을 위해 죽은 코드를 늘린 것이다.

지운 것 — 저장소 전체에서 **95줄 / 10파일**:

| 파일 | 줄 |
|---|---|
| `matchGameAI.tsx` · `matchGamePG.tsx` | 각 24 |
| `MiniKeyboardMap.tsx` | 8 |
| `MusicTrainingScreen.tsx` | 12 (+ 죽은 `shadowOpacity` 공유값 3줄) |
| `flashcards/index.tsx` · `new/index.tsx` · `WordFlashcard.tsx` · `MissionProgressIcon.tsx` · `DrumGameOverScreen.tsx` | 각 4 |

**`elevation`은 한 줄도 건드리지 않았다.** 안드로이드의 진짜 그림자는 그쪽이고,
지운 넷은 리액트 네이티브 타입에서 `ShadowStyleIOS`로 묶인 iOS 전용 속성이다.
피아노 건반의 2.5D 입체감도 `elevation: 10`이 그대로라 유지된다.

곁들여 나온 것:
- `MusicTrainingScreen`의 `shadowOpacity` **공유값(reanimated)이 죽은 코드**였다.
  건반을 누를 때 0.06으로 낮추고 놓으면 되돌리는 애니메이션인데, 그리는 쪽이 iOS 전용이라
  안드로이드에서는 처음부터 아무 일도 하지 않았다. 값·핸들러까지 함께 지웠다
  (`translateY` 눌림 애니메이션은 그대로다)
- `app/_layout.tsx:132`의 `shadowOpacity`는 **통째로 주석 처리된 옛 스타일 안**이라 두었다.
  주석 정리는 이번 지시의 범위가 아니다
- `Platform.OS === 'ios'` 분기, `app.json`의 iOS 설정, `ios/` 디렉터리는 **애초에 없다**

`CLAUDE.md`에 **규칙 4 — 안드로이드 전용 앱이다**를 넣었다.

| 퀴즈 모드에서 답으로 칠 때 | 정답 제출 분기에도 넣었다 |
| ↻ 다시 듣기 · 퀴즈 출제음 | **진동이 없어야 정상이다** (듣는 동작) |
| 세기 | 과하면 `ImpactFeedbackStyle.Medium` → `Light` 한 단어만 바꾸면 된다 |
