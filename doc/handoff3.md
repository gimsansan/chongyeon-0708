### 0. 인계문을 handoff3으로 옮겼다

사용자 지시다. `handoff2.md`는 **세션 28~33 아카이브**로 머리 3줄만 바꿨고 본문은 그대로 뒀다.
`CLAUDE.md`의 규칙 2-2 / 2-3 / 2-4가 가리키는 "현재 인계문"도 함께 `handoff3.md`로 바꿨다 —
**이걸 안 바꾸면 다음 세션이 handoff2를 읽고 이 파일을 못 본다.**

주의사항은 **복사하지 않고 handoff2·handoff1을 가리키게** 했다. 통째로 옮기면 원본이 흐려지고,
「되돌리면 안 되는 것」은 지금도 전부 유효해서 취소선 대상이 아니다.

### 1. 내가 방향을 잘못 말했다 — 그리고 그게 설계를 바꿨다

디자인 제안에서 "드럼 탭은 회전하니 가로에서 버튼이 잘린다"고 했는데 **틀렸다.**
`app.json`의 `"orientation": "default"`만 보고 판단한 것이다.

실제 방향은 `app/(tabs)/_layout.tsx:57`의 `LANDSCAPE_ROUTES = ['/activity', '/guitar']`가
정한다. `useOrientationForRoute()`가 경로마다 `lockAsync()`를 다시 걸어서, 목록에 있으면 가로,
**나머지는 전부 `PORTRAIT_UP`**이다. 드럼도 learn도 목록에 없다.

> **`app.json`은 출고 설정이고 `_layout.tsx`는 실행 중 명령이다. 나중에 말한 쪽이 이긴다.**
> 방향을 확인할 때 `app.json`만 보면 안 된다.

그래서 제안했던 「가로에서 버튼 잘림」 대응은 **넣지 않았다.** 일어날 수 없는 상황이고,
안 쓰는 가로 분기만 코드에 남는다.

### 2. 결과 화면 (`7d2c55f`)

**전제 하나**: `DrumGameOverScreen`은 이름과 달리 **드럼과 learn 둘이 함께 쓴다**

지금 스타일은 사실상 드럼만 보고 잡혀 있었다.

| 고친 것 | 왜 |
|---|---|

| 등급표 `RESULT_TIERS` 하나로 | 메시지와 색이 나뉘어 있으면 한쪽만 고쳐져 어긋난다 |

**범위 밖인데 딸려온 것**: 메시지를 등급표로 옮기며 선행 공백(`" 완벽해요!"`)이 없어졌다.
나머지 3순위(0/0이면 「완벽해요!」 · 위계 · 숫자 카운트업)는 **그대로 뒀다.**

### 3. learn을 드럼과 같은 방식으로 (같은 커밋)

learn은 결과를 **페이지 안에** 끼워 넣고 있었다(`gameContentInner`, 위 정렬, 스크림 없음).
드럼과 같은 전체 오버레이(`gameOverOverlay`, 검은 스크림 `rgba(0,0,0,0.7)`, 중앙)로 바꿨다.

**`WordGame`은 그대로 언마운트한다.** 오버레이로 덮기만 하고 뒤에 살려두면 오디오·타이머가
남는다 — 세션 20~27에 잡았던 그 계열의 문제다. `{isGameOver ? 결과 : 게임}`을
`{!isGameOver && 게임}` + 별도 오버레이로 나눈 이유가 이것이다.

`npx tsc --noEmit` 새 오류 0건. 남은 `hooks/useSyncGameData.ts(44,51)`은 세션 29에서
무관한 기존 항목으로 확인된 것이다.

### 4. iOS 전용 코드를 걷어냈다 — 규칙 4 신설

사용자가 알려줬다. **이 앱은 안드로이드 모바일 앱이고 iOS 대응을 하지 않는다.**

`shadow*` 네 줄을 **새로 넣은 참이었다.** 대상이 아닌 플랫폼을 위해 죽은 코드를 늘린 것이다.

지운 것 — 저장소 전체에서 **95줄 / 10파일**:

| 파일 | 줄 |
|---|---|
| `matchGameAI.tsx` · `matchGamePG.tsx` | 각 24 |
| `MiniKeyboardMap.tsx` | 8 |

### 2. learn 메인 화면 디자인 개선 *(미커밋)*

사용자 요청 — 「`DrumGameOverScreen`을 고쳐 준 것처럼 메인 화면도」. 범위는 사용자가 골랐다:

**가장 큰 것 — 난이도 버튼이 폭을 넘고 있었다.** `learnDifficultyButtonSize`가 `140/160` **고정**이라
360dp 기기에서 `140×2 + gap15 = 295`가 쓸 수 있는 폭 270(`화면폭 − 마진40 − 패딩50`)을 **40px 넘겨**
안쪽 여백을 잠식했다. 폭에서 역산한 상한을 걸고, **버튼 안의 별·이름·패딩을 버튼 크기에 비례**시켰다
(`scaleFromPhoneButton`) — 버튼만 줄이면 내용이 넘치기 때문이다.

비율은 **기존 폰 값**(버튼 140 · 별 60 · 이름 18 · 패딩 20)에서 뽑았다. 그래서 **390dp 이상 폰은 그대로다.**

### 4. flashcards 탭 — learn과 같은 묶음으로 (`8513f1b`)

사용자 요청 — 「learn 탭 ui를 개선시켜 준 것처럼」. 범위는 사용자가 골랐다: **「learn과 같은 범위」**
(반응형 + 대비 + 접근성 + 색 토큰화 + 죽은 스타일 정리). 함께 물은 **하단 네비 위치는
「그대로 둔다」를 골랐다** — 아래 주의사항 참고.

**가장 큰 것 — learn 난이도 버튼과 같은 구조의 문제였다.** 카드 높이는 `cardStackHeight`
(= `min(400, 높이×0.4)`)로 반응형인데 **카드를 밀어내는 값만 고정**이었다:
`cardStackMarginTop: 150` + `topCard.marginTop: 70` = **220 고정**.

| 기기 높이 | 카드 하단(절대) | 하단 네비 시작 | |
|---|---|---|---|
| 640 (전) | 560 | 512 | ❌ **48px 겹침** |
| 640 (후) | 502 | 512 | ✅ 10px 여유 |
| **868 (현재 실기기)** | 651 | 732 | ✅ 전·후 동일 |

`FLASHCARD_CARD_TOP_TOTAL = round(clamp(높이 × 0.2535, 120, 220))`으로 두고 **150 : 70 비를
유지**해 나눈다. 868에서 정확히 220 → 150/70이라 **현재 기기는 한 픽셀도 안 바뀐다.**

> **둘을 하나로 합치지 않은 이유**: 역할이 다르다. `cardStackMarginTop`은 흐름 안에서 자리를
> 차지해 **스크롤 길이에 반영**되고, `topCardMarginTop`은 절대배치된 카드만 내려 **자리를 차지하지 않는다.**

**곁들여 나온 것 — 배지로 날아가는 애니메이션이 빗나가고 있었다.** `handleCompleteCard`가 재는
대상은 카드가 아니라 **스택 래퍼**(`cardStackRef`)인데, 카드는 그 안에서 70px 더 내려가 있다.
그래서 카드가 배지보다 70px 아래에 가서 멈췄다. 밀어내기를 기기별로 바꾸면 이 오차도 기기마다
달라지므로 같이 고쳤다 — `cardCenterY`에 `flashcardsTopCardMarginTop`을 더한다.

나머지:

| 고친 것 | 왜 |
|---|---|
| 제목을 **옅은 흰 pill**로 받쳤다 | learn과 같은 처리. **flashcards는 learn과 달리 흰 오버레이 22%도 없어** 조건이 더 나빴다 |
| 진행도 숫자에도 같은 pill | 역시 배경 사진 위에 맨몸으로 얹혀 있었다 |
| 진행바 레일 흰색 · 눈금 `successOnWhite` | 레일 `successLight`(#C8E6C9) · 눈금 `success`(#7cbd7e)가 밝은 사진 위에서 거의 안 보였다. 눈금(10px)은 레일(3px)보다 커서 사진 위로 삐져나온다 |
| 비활성 화살표 아이콘 `borderGray` → `textSecondary` | #BDBDBD on #E0E0E0 = **1.2:1**이라 아이콘이 사라졌다. #666이면 4.4:1이고, 활성(#333)과는 여전히 구분된다 |

| `isFirstCard` · `isLastCard` 두 변수 | 같은 판정이 버튼마다 세 곳(onPress·스타일·아이콘 색)에 흩어져 있었다 |
| 접근성 속성 | 화살표·학습완료·배지·모달 닫기·완료 카드 항목·다시 하기 — **하나도 없었다** |
| 진행바 세로 위치에 상한 | `높이 × 0.2`라 태블릿(1280dp)에서 256까지 내려가 카드와 붙었다. 폰 176 / 태블릿 190 상한. **868에서는 174로 종전과 같다** |
