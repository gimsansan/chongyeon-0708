### 0. 인계문을 handoff3으로 옮겼다

사용자 지시다. `handoff2.md`는 **세션 28~33 아카이브**로 머리 3줄만 바꿨고 본문은 그대로 뒀다.

### 1. 내가 방향을 잘못 말했다 — 그리고 그게 설계를 바꿨다

디자인 제안에서 "드럼 탭은 회전하니 가로에서 버튼이 잘린다"고 했는데 **틀렸다.**
`app.json`의 `"orientation": "default"`만 보고 판단한 것이다.

실제 방향은 `app/(tabs)/_layout.tsx:57`의 `LANDSCAPE_ROUTES = ['/activity', '/guitar']`가
정한다. `useOrientationForRoute()`가 경로마다 `lockAsync()`를 다시 걸어서, 목록에 있으면 가로,
**나머지는 전부 `PORTRAIT_UP`**이다. 드럼도 learn도 목록에 없다.

> **`app.json`은 출고 설정이고 `_layout.tsx`는 실행 중 명령이다. 나중에 말한 쪽이 이긴다.**
> 방향을 확인할 때 `app.json`만 보면 안 된다.

그래서 제안했던 「가로에서 버튼 잘림」 대응은 **넣지 않았다.** 일어날 수 없는 상황이고,
안 쓰는 가로 분기만 코드에 남는다.

### 2. learn 메인 화면 디자인 개선 *(미커밋)*

사용자 요청 — 「`DrumGameOverScreen`을 고쳐 준 것처럼 메인 화면도」. 범위는 사용자가 골랐다:

**가장 큰 것 — 난이도 버튼이 폭을 넘고 있었다.** `learnDifficultyButtonSize`가 `140/160` **고정**이라

(`scaleFromPhoneButton`) — 버튼만 줄이면 내용이 넘치기 때문이다.

비율은 **기존 폰 값**(버튼 140 · 별 60 · 이름 18 · 패딩 20)에서 뽑았다. 그래서 **390dp 이상 폰은 그대로다.**

learn에서 쓰면 **같은 값이 두 곳에 생긴다** — 세션 34가 `RESULT_TIERS`에서 경계한 바로 그 어긋남이다.

- `COLORS.successOnWhite` (`#4E9A51`) — 지역 상수를 걷고 결과 화면도 이걸 쓴다. **값이 같아 화면 변화 없음**
- `COLORS.backgroundSoft` (`#F0F2F5`) — learn 바탕. 결과 화면 주석이 이 값을 이름으로 가리키던 색이다

**거짓 주석 하나를 정정했다.** `index.tsx`에 「모든 콘텐츠를 하나의 흰색 카드(gameSection) 안에 통합」이라
적혀 있었지만 `gameSection`에는 **배경색이 없다.** 카드가 아니다.

**손대지 않은 것**: 같은 난이도를 다시 눌러도 게임이 리셋되는 동작, `starCell*` 3분할(계단 배치 의도로 보임).

### 3. 「시작하기」를 살짝 위로 *(미커밋)*

`readyActionWrapper`가 `marginTop: 'auto'`로 바닥에 붙는데 아래 여백은 `contentBottomPadding` 8px뿐이라
화면 끝에 닿아 보였다. `getWordGameMetrics`에 **`startOffsetY`**를 새로 두고 높이 비례로 올린다.
고정 px로 올리면 세로가 짧은 기기에서 과해진다.

### 4. 실기기 제원을 `adb`로 확인했다

「현재 화면 높이는?」이라는 물음에 어림잡지 않고 붙어 있는 기기를 직접 읽었다.
**`adb`는 PATH에 없고 SDK 안에 있다**: `%LOCALAPPDATA%/Android/Sdk/platform-tools/adb.exe`

| 항목 | 값 |
|---|---|
| 모델 | `SC-01M` (Galaxy Note10+ docomo) |
| 물리 / 적용 해상도 | 1440×3040(560dpi) / **1080×2280 @ 420dpi** (배율 2.625) |
| 폭 · 전체 높이 | **411dp** · **868dp** |
| 시스템 바 제외 높이 | 788dp (`h788dp`, app 영역 1080×2069) |

Expo SDK 57 / RN 0.86이라 안드로이드 edge-to-edge가 항상 켜져 있고,
`learn/index.tsx`가 `insets.top`으로 직접 패딩을 주고 배경을 `screenHeight`로 까는 것도 그 전제다.
그래서 `Dimensions.get('window')`에는 **868**이 들어간다고 본다.

> **이 기기에서 2번 작업으로 실제 달라지는 치수는 `startOffsetY` 19 하나다.**
> 폭이 411이라 난이도 버튼은 140 그대로고, `learnGameContentMarginTop`도 상한 50에 걸려 기존값과 같다.
> 나머지(pill · elevation · 선택 색 · 접근성)는 치수가 아닌 시각·속성 변화다.

### 되돌리면 안 되는 것 (세션 34)

- **게이지 크기를 고정 px로 되돌리지 말 것.** `220×40`은 태블릿에서 카드만 넓어지고
  게이지는 그대로 남는다. 실측(`onLayout`) → 카드 폭 추종이라야 두 호스트 모두 맞는다.
  **실측 전 하한(160)도 지울 것이 아니다** — 크게 어림잡으면 learn에서 한 프레임 삐져나온다.
- **`RESULT_TIERS`를 메시지와 색으로 다시 나누지 말 것.** 나뉘면 한쪽만 고쳐져 어긋난다.
- **등급 색을 원색(`#FFD700` · `#7cbd7e`)으로 되돌리지 말 것.** 흰 카드 위에서 2.2:1이라
  큰 글씨 기준(3:1)에 못 미친다. 반대로 **버튼 배경·테두리는 브랜드 초록 그대로다** —
  글자에 쓸 때만 `GREEN_ON_WHITE`다.
- ~~**`shadow*`를 지우고 `elevation`만 남기지 말 것.**~~ → **같은 세션에 뒤집혔다.**
  이 앱은 **안드로이드 전용**이라 `shadow*`는 아무 일도 하지 않는다. **그림자는 `elevation`으로만 낸다**
  (`CLAUDE.md` 규칙 4). learn의 밝은 배경에서 카드가 묻는 것은 **옅은 테두리**로 푼다.
- **learn에서 `WordGame`을 오버레이 뒤에 살려두지 말 것.** 지금은 `{!isGameOver && 게임}`으로
  언마운트한다. 덮기만 하면 오디오·타이머가 뒤에 남는다.
- **가로 대응을 넣지 말 것.** 드럼·learn은 `LANDSCAPE_ROUTES`에 없어 `PORTRAIT_UP` 고정이다.
  안 쓰는 분기만 늘어난다.
- **화면 방향을 `app.json`으로 판단하지 말 것.** `"orientation": "default"`는 출고 설정일 뿐이고,
  실제로 정하는 것은 `app/(tabs)/_layout.tsx`의 `LANDSCAPE_ROUTES` + `lockAsync()`다.
  **나중에 실행되는 쪽이 이긴다.** 세션 34에서 이걸 거꾸로 읽고 없는 문제를 제안했다.

### 되돌리면 안 되는 것 (세션 35)

- **`audioPlayer.progress`를 죽은 코드로 보고 지우지 말 것.** 진행 바가 사라져 안 쓰이는 것처럼 보이지만
  `WordFlashcard.tsx:178`이 `Waveform`에 넘겨 쓴다. 지우면 파형이 멈춘다.
- **난이도 버튼 치수를 고정 px로 되돌리지 말 것.** `140/160`은 360dp에서 40px 넘쳐 여백을 먹었다.
  폭에서 역산한 상한이라야 작은 폰·태블릿 둘 다 맞는다.
- **버튼 안 치수(별 · 이름 · 패딩)를 버튼 크기와 따로 두지 말 것.** 버튼만 줄면 내용이 넘친다.
  `scaleFromPhoneButton`이 그 연결이다.
- **폰 상한 140을 올리지 말 것.** 390dp 이상에서 기존 화면이 그대로여야 한다는 것이 이 값의 뜻이다
  (세션 34에서 세운 「폰 값은 그대로, 태블릿만」 원칙).
- **`gameSection`에 배경색을 주지 말 것.** 카드가 아니다. 사용자가 「흰 카드로 묶기」를 **고르지 않았다** —
  배경 이미지를 살리는 쪽을 골랐다. 주석은 그렇게 고쳐 두었다.
- **`COLORS.successOnWhite`를 다시 파일 지역 상수로 내리지 말 것.** 결과 화면과 learn이 함께 쓴다.
  값이 두 곳에 있으면 한쪽만 고쳐져 어긋난다. **배경·테두리는 `COLORS.success` 그대로다** — 글자만 이 값이다.
- **화면 치수를 어림잡지 말 것.** 기기가 붙어 있으면 `adb`로 읽는다 —
  `%LOCALAPPDATA%/Android/Sdk/platform-tools/adb.exe`의 `wm size` · `wm density` ·
  `dumpsys window displays`(`w411dp h788dp`)가 답을 준다. **PATH에는 없다.**
