## 2. 사용자
- 제스처만 쓰고 뒤로가기를 모르는 사람
- 런처/커스텀 네비로 뒤로가기 버튼이 안 보이는 기기
- 가로 화면에서 제스처가 헷갈리는 경우
- “앱 안 버튼으로 나가야지”라고 생각하는 사람

그래서 **시스템 뒤로가기만 믿지 말고, 피아노·기타 화면에 작은 ‘나가기’를 두는 게 안전하다**고 한 겁니다.
탭바를 숨기는 UX는 유지하고, 갇힌 느낌만 막는것  이런 의견이 있음 간

## 2. Claude
그 의견에 동의한다. 피아노·기타는 탭바를 숨긴 채 가로로 들어가서, 시스템 뒤로가기만으로는 못 나가는 사람이 있다. 탭바는 그대로 숨기고, 화면 안에 작은 ‘나가기’만 두면 갇힌 느낌만 막을 수 있다. 지금 그 두 화면에는 앱 안 나가기 버튼이 없다. 간

## 3. 사용자
되도록이면 면적을 덜 차지하면서 뒤로가기 인상을 줄수 있는 ui 로 하고 싶은데 제안을 해줄래? 두 탭 공통으로 넣을 생각이다. 이해?

## 3. Claude
이해한 건 이것이다. **피아노·기타 두 탭에 같은 UI**로, 탭바는 숨긴 채 **면적은 최소**로 두고, 봐도 **뒤로가기**로 읽히는 나가기를 넣는다. 맞나?

맞다면 추천은 하나다.

**좌상단, 아이콘만 있는 떠 있는 뒤로 화살표.**
레이아웃을 밀어내지 않고 코너에만 얹는다. 글자(`나가기`)는 빼는 게 제일 작다.

- 아이콘: `arrow-back` (피아노 옥타브 버튼의 `chevron-back`과 겹치지 않게)
- 위치: 두 화면 모두 **왼쪽 위** (기타 미션 아이콘은 오른쪽 위)
- X 닫기는 비추천. 모달 닫기로 읽힌다.

공통 컴포넌트 하나 만들어 두 화면에 같은 자리·같은 동작으로 넣으면 된다. 이 안으로 갈까?

## 4. 사용자
화면에 보이는 넣는 위치도 중요하다. 콘텐츠에 방해가 되지 않는 선에서 해야함.

## 4. Claude
이전에 말한 **좌상단 떠 있는 버튼은 피아노에서 콘텐츠를 가린다.** 옥타브 낮춤·낙하노트·왼쪽 건반이 그 자리다.

공통으로 지킬 원칙은 이것이다. **연주 영역이 아니라, 이미 있는 조작 칸(크롬) 안에 넣는다.** 아이콘은 같고, 좌표만 각 화면 크롬에 맞춘다.

- **피아노** (`screens/MusicTrainingScreen.tsx`): 하단 제어반 **맨 왼쪽**. 건반·낙하노트 밖이다. 우상단은 미션, 하단 오른쪽은 시작/반복이다.
- **기타** (`app/(tabs)/guitar/_layout.tsx`): 왼쪽 사이드바 **맨 위**(SCORE 위). 지판을 안 가린다. 우상단은 미션이다.

피해야 할 곳: 피아노 좌상단, 기타 지판, 양쪽 우상단(미션).

같은 코너에 고정하려면 **좌하단**만 양쪽 다 크롬이다. 그래도 떠 올리기보다 제어반/사이드바에 붙이는 편이 안 가린다.

## 8. 사용자
나갔다 들어오면 언마운트 되는것은 아니지?

## 8. Claude
맞다. **나갔다 들어와도 언마운트되지 않는다.**

`Tabs`에 `unmountOnBlur`가 없어서, 한 번 들어간 피아노·기타는 탭만 바꿔도 트리에 남는다. 나가기 버튼의 `router.back()` / `replace(drum)`도 같은 탭 전환이라 화면은 유지된다.

그래서 훈련 점수·난이도 같은 state는 그대로고, 소리 정지는 언마운트가 아니라 `useStopAudioOnBlur`의 **포커스 아웃**으로 한다.
