### 헷갈리기 쉬운 것 — **익힘모달 ≠ 미션모달**

`modalContent`는 **판 스타일 이름이지 화면이 아니다.** 두 파일에 같은 키가 있고
**StyleSheet가 파일마다 따로라 이름만 같다.** 한쪽을 고쳐도 다른 쪽은 그대로다.

| | **익힘모달** | **미션모달** |
|---|---|---|
| 파일 | `app/(tabs)/flashcards/index.tsx` | **`components/MissionProgressIcon.tsx`** (`components/game/`가 아니다) |
| 여는 것 | 익힘배지 | 미션아이콘 (게임·악기 화면 우상단) |
| 스위치 | `showCompletedModal` | `modalVisible` |
| 모양 | 아래서 올라오는 노란 시트 (`backgroundStar` `#FFF9E6`) | 가운데 흰 박스 |

> **「`modalContent`를 고쳐 달라」는 말은 어느 화면인지 알 수 없다.**
> 화면을 말할 때는 **익힘모달 / 미션모달**, 판만 가리킬 때 `modalContent`.

### 0. 인계문을 handoff4로 옮겼다

사용자 지시다. `handoff3.md`는 **세션 34~37 아카이브**로 머리만 바꾸고 본문은 그대로 뒀다
(세션 34가 handoff2를 넘길 때와 같은 방식이다).
`CLAUDE.md`의 규칙 2-2 / 2-3 / 2-4가 가리키는 "현재 인계문"도 함께 `handoff4.md`로 바꿨다 —
**이걸 안 바꾸면 다음 세션이 handoff3을 읽고 이 파일을 못 본다.**

주의사항은 **복사하지 않고 handoff3·handoff2·handoff1을 가리키게** 했다.

### 1. 이름부터 맞췄다 — 그리고 내가 한 번 틀렸다

사용자가 화면 부위 이름표를 줬다(위 「화면 부위를 부르는 이름」). 코드와 대조해 12개가
전부 실제 스타일 키와 맞는 것을 확인하고, 표에 없던 넷(**VS** · **단어 글자** ·
**단어 스피커** · **카드박스 오버레이**)에 이름을 더했다.

그런데 내가 표를 옮겨 적으며 **「익힘모달 = `modalContent`」**라고 썼고, 사용자가 정정했다.
`modalContent`는 **판 스타일 이름**이고, `components/MissionProgressIcon.tsx`에도
**같은 키가 따로 있다.** 파일마다 StyleSheet가 따로라 이름만 같은 것인데,
그대로 두면 「`modalContent` 고쳐 줘」가 어느 화면인지 알 수 없다.

> **스타일 키 이름을 화면 이름으로 쓰지 말 것.** 위 「익힘모달 ≠ 미션모달」 표가 이 실수의 결과다.

### 2. 내가 또 방향을 잘못 말했다 — 진행바 마커

「마커가 90%까지만 움직여 끝에 닿지 않는다」고 보고했는데 **틀렸다.**
레일이 래퍼 폭의 **90%**라 `progress × 90%`는 **레일 길이와 정확히 같다.** 마커는 전 구간을 돈다.

실제 문제는 **기준이 셋이었던 것**이다:

| | 무엇을 기준으로 삼았나 |
|---|---|
| 레일 (`progressLine`) | 폭 90% + 가운데 정렬 → 래퍼 기준 **5%~95%** |
| 마커 | `left: 비율 × 90%` + `marginLeft: -1` → 중심이 늘 **4px 왼쪽** |
| 눈금 | `space-between` 컨테이너 → **또 다른 기준** |

셋을 **`시작 5% + 비율 × 90%` 한 식**으로 묶었다(`railPercent()`). 마커의 `marginLeft`도
`-1`에서 **`-마커폭/2`**로 바꿨다 — 「중심이 그 지점을 가리킨다」는 뜻이 값에 드러나야 한다.

> **`app.json`/`_layout.tsx` 때(세션 34)와 같은 종류의 실수다.**
> 값 하나(`Math.min(90, …)`)만 보고 「잘린다」고 단정했다. 그 90이 **레일 폭과 같은 수**라는 것을
> 같이 보지 않았다. 퍼센트는 **무엇의 퍼센트인지**까지 봐야 한다.

### 3. 눈금이 카드 수를 따라간다 (`d38df37`)

`[0, 1, 2, 3, 4, 5]` **하드코딩**이라 카드가 20장이든 3장이든 늘 6개였다.
**눈금 하나 = 카드 한 장**으로 바꾸고, 레일에 **지나온 만큼 채움**을 깔았다.

- 채움 `progressLineFill` — 초록(`successOnWhite`). 눈금만으로는 어디까지 왔는지 읽기 어렵다
- **지나온 눈금은 흰색으로 뒤집는다.** 초록 채움 위에 초록 눈금을 두면 묻는다
- 조건은 `i < currentIndex`다. `i <= currentIndex`로 하면 **첫 카드에서 채움이 0인데
  눈금이 흰색**이 되어 흰 레일 위에서 사라진다. 현재 위치의 눈금은 마커가 덮는다
- 크기는 `getProgressTickSize(카드수)` — 레일을 카드 수로 나눈 한 칸의 절반을 넘지 않게 줄이되 하한 4

| 기기 | 레일 폭 | 20장일 때 눈금 |
|---|---|---|
| **411dp (실기기)** | 343 | **10 — 종전과 같다** (계산값 9.93) |
| 320dp | 261 | 8 (15장을 넘길 때부터 줄어든다) |

**곁들여 나온 것 — 마커 아이콘이 잘리고 있었다.** 상자가 32px인데 아이콘이 36px이고
`overflow: 'hidden'`이라 **좌우 2px씩 깎여 있었다.** `overflow`만 뺐다.

### 4. 전체듣기 중에 파형이 없었다 (같은 커밋)

조건이 `showWaveform && !isPlayingAll`이라, **소리는 이어서 나는데 파형 자리만 비어 있었다**
(자리는 `waveformContainer`가 늘 차지한다). `!isPlayingAll`을 뺐다.

**어느 단어가 울리는지도 표시가 없었다.** 전체듣기는 단어1 → 단어2로 혼자 넘어가는데
두 장을 똑같이 흐리게만 했다. 지금은 울리는 쪽을 강조하고 **반대쪽만** 흐리게 한다.

- `wordCardPlaying` — 초록 테두리 + 연한 초록 배경(`backgroundSuccess`) + `elevation: 8`
- **테두리는 늘 자리를 차지한다** (`borderWidth: 2` + `borderColor: 'transparent'`).
  재생 중에만 색을 넣으므로 **카드 크기가 흔들리지 않는다**
- 스피커 아이콘: 쉴 때 `volume-medium-outline`, 울릴 때 `volume-high` + `successOnWhite`
- 접근성 속성(`Role` · `Label` · `State({ disabled, busy })`)이 **하나도 없었다**

Yoga는 `minWidth`가 **border-box**라, 단어가 2자 이하(데이터 최대 '고기'·'머리')면
`64 + 패딩 40 + 테두리 4 = 108 < 120`이라 **폭은 그대로**다. 높이만 4px 는다.

### 5. 완료화면에서 `1 / 0`이 떴다 (같은 커밋)

남은 카드가 0인데 진행숫자가 `{currentIndex + 1} / {cardCount}`를 그대로 그렸다.
**진행바·진행숫자를 통째로 숨긴다** — 가리킬 진행이 없다.

**학습완료 버튼도 `disabled`로 막았다.** `handleCompleteCard`가 맨 앞에서 `return`하므로
아무 일도 안 하는데 **눌리는 시각 반응은 그대로 났다** (세션 36에서 화살표에 한 것과 같은 처리).
글자색도 `textSecondary`로 내렸다 — 회색 바탕 위 흰 글자는 **1.5:1**이라 읽히지 않는다.

### 6. 제스처를 지웠다 (같은 커밋)

**사용자가 지울 것과 남길 것을 직접 나눠 줬다.**

| 지운 것 | 남긴 것 |
|---|---|
| `PanGestureHandler` (`enabled={false}` 포함) | `panX` · `panY` · `scale` · `opacity` · `rotation` |
| `handleGestureEvent` · `handleSwipe` | `animateSwipe` · `resetAnimation` · `handleCompleteCard` |
| `undoStackRef` (스와이프 전용) | `GestureHandlerRootView` |
| `LAYOUT.dropZoneThreshold` · `dropZoneThresholdRatio` | |
| `animateSwipe`의 `'down'` 분기 (타입도 `'left' \| 'right'`로) | |

`'down'`은 **아래로 떨어뜨려 학습완료하던 스와이프 전용**이었다. 지금 학습완료는
`handleCompleteCard`의 「익힘배지로 날아가기」가 따로 하고, 그쪽은 `Animated.parallel`을
직접 쓰므로 겹치지 않는다. **`panY`는 그 날아가기(`:211`)가 쓰므로 남는다.**

> `'down'`을 지울지는 **내가 물었고 사용자가 결정했다.** 지시에 「남길 것: `animateSwipe`」가
> 있어서 내 판단으로 안쪽 분기를 지우지 않고 물은 것이다.

**곁들여 죽은 상태 셋을 지웠다** — `completionMessage`·`setCompletionMessage`는 읽는 곳이 없고,
`completionTimeoutRef`는 **설정하는 곳 없이 정리만 하는 `useEffect`**를 달고 있었다.

`npx tsc --noEmit` 새 오류 0건. 남은 `hooks/useSyncGameData.ts(44,51)`은 세션 29에서
무관한 기존 항목으로 확인된 것이다.

### 0. 방향을 먼저 물었다

이 선택이 아래 1번·2번의 근거다.

### 1. 익힘모달 — 겉모습보다 동작에 문제가 더 있었다

**`Modal`이 아니라 조건부 `View` + `zIndex: 1000`이었다.**
그래서 **안드로이드 뒤로가기로 닫히지 않았다.** 미션모달
(`components/MissionProgressIcon.tsx`)은 처음부터 `Modal` + `onRequestClose`를 쓰고 있었다 —
**같은 앱 안에서 두 모달의 뼈대가 달랐다.**

곁들여 나온 것 셋:

- **`ScrollView`의 padding이 `style`에 있었다.** RN에서는 `contentContainerStyle`이어야
  내용 여백이 된다. `style`에 주면 스크롤 상자만 줄어 **마지막 항목 아래 여백이 안 생긴다**
- **스크롤 상자가 줄어들 수 없었다.** 시트가 `maxHeight: '80%'`인데 `flexShrink`가 0(기본)이라
  내용 높이 그대로 잡혔다 — **완료 카드가 많으면 아래가 잘리고 스크롤도 안 됐다.**
  `flexShrink: 1`을 줬다. 이건 겉모습을 보다 발견한 것이다
- **바닥 인셋을 안 봤다.** `insets.bottom`이 없어 「전체 다시 하기」가 제스처바에 물렸다

겉모습은 넷을 고쳤다:

| | 전 | 후 |
|---|---|---|
| 2열 정렬 | `minWidth: '45%'` — 단어가 길면 항목이 늘어나 **줄마다 폭이 달랐다** | 폭 고정 `48%` + 컨테이너 `space-between` |
| 항목 바탕 | `backgroundLight`(#f0f0f0) | 흰색 + `border` 테두리 (시트가 `backgroundStar` #FFF9E6이라 회색은 구분이 약했다) |
| 되돌리기 | `textLight`(#999) 아이콘만 오른쪽 아래 — **흰 카드 위 2.8:1** | 「↺ 되돌리기」 칩 (`backgroundSuccess` 바탕 + `successOnWhite`) |
| 손잡이 | 없음 | `modalHandle` — 아래서 올라오는 판이라는 표시 |

`animationType="slide"`라 시트가 올라온다. **전에는 애니메이션이 아예 없어 즉시 튀어나왔다.**

**2열 폭 계산** — `48% × 2 = 96%`라 남는 4%가 열 사이 간격이 된다.
`columnGap`이 아니라 `space-between`인 이유는, 마지막 줄에 항목이 하나만 남았을 때
**늘어나지 않고 왼쪽에 붙게** 하기 위해서다.

|---|---|---|---|
| **411dp (실기기)** | 379 | 182 | 15 |
| 320dp | 288 | 138 | 12 |

`accessible`을 끄지 않는 한 켜져 있다 — 저장소의 RN 0.86에서 직접 확인했다:

```
node_modules/react-native/Libraries/Components/Touchable/TouchableOpacity.js:303
  accessible={this.props.accessible !== false}
```

켜진 요소의 자식은 **한 덩어리로 묶여** 토크백 초점이 따로 가지 않는다.
즉 닫기 버튼 · 완료 항목 20여 개 · 되돌리기 칩 · 「전체 다시 하기」가 **전부 한 덩어리**였고,
거기에 `Role`·`Label`만 더하면 **그 묶임이 굳는다.**

사용자에게 두 길을 물어 **형제 배경**을 골랐다. 절대배치 `Pressable`을 시트의 **형제**로 내리고
거기에 `Role`·`Label`을 달았다. 배경색도 `modalOverlay` → `modalBackdrop`으로 옮겼다.
**`components/MissionProgressIcon.tsx:129-133`이 이미 그 형태다** — 새로 지어낸 구조가 아니다.

> **보류 항목의 문구를 그대로 믿고 고치지 말 것.** 적을 때 본 것은 「없는 속성」이었고,
> **왜 없었는지**는 고치러 가서야 보였다. 0-2절은 색인이지 진단서가 아니다.

### 3. 토큰 셋 중 하나만 값이 바뀐다

| 자리 | 바꾼 것 | 기기에 미치는 영향 |
|---|---|---|
| `completeButton.paddingHorizontal` | `LAYOUT.completeButtonPaddingH` (20) | **없음** — 고정값 그대로 |
| `completionText.marginBottom` | `LAYOUT.completionTextMarginBottom` (10) | **없음** — 고정값 그대로 |
| `completedCardImage.gap` | `LAYOUT.spacingSM` | **태블릿만 8 → 10.** 폰은 그대로 |

`gap`은 값이 `spacingSM`의 폰 값과 같아 새 토큰을 만들지 않았다. 320dp의 완료 항목은
안쪽 폭이 108로 빠듯한데 **그 폭은 건드리지 않는다.**

### 4. 주석이 코드와 반대였다 — **코드가 맞다**

`resetAnimation` 위에 「`Animated.timing`을 써서 부드럽게 원위치로」라 적혀 있었지만
본문은 `setValue` 다섯 줄뿐이다. 부르는 자리를 셋 다 확인했다 —
`handlePrevCard`·`handleNextCard`의 `animateSwipe` 완료 콜백, `handleCompleteCard`의
배지로 날아간 뒤. **모두 카드가 이미 화면 밖으로 나가고 다음 카드로 바뀐 뒤**라,
timing으로 되돌리면 새 카드가 **밖에서 날아 들어오는 것처럼** 보인다.
**주석을 코드에 맞췄다** — 「즉시가 맞는 이유」를 적었다.

### 5. 재점검 3건 — 고치지 않고 0-2절로

규칙 5대로 **한 번만** 다시 훑었다. `elevation` 리터럴 셋 · 슬래시의 인라인
`marginHorizontal: 6` · `measure` 콜백의 안 쓰는 인자 넷. **고칠지는 다음 차례에 고른다.**

이 파일의 터치 요소는 이제 **9개 전부** `Role`·`Label`을 갖췄다
(`disabled`인 넷은 `accessibilityState`도).

> 이력의 「터치/`Role`」 칸 **22 / 9는 grep 줄 수**라 주석 속 「`TouchableOpacity`」도 센다.
> 세션 41의 20 / 8과 **같은 명령으로 잰 값**이라 비교는 되지만, **요소 수가 아니다.**

### 6. 점검표 3절에 갈래를 더하고 낡은 수치를 뺐다

3절에 「**터치를 감싸는 것이 자식을 삼키지 않는지**」를 더했다 (2번의 근거와 정해진 답).
같은 절에 있던 「터치 166개 중 18개」는 **적지 말라고 규칙에 써 놓고 남아 있던 수치**라 뺐다 —
실측은 이력이 갖는다.

`npx tsc --noEmit` 새 오류 0건. 남은 `hooks/useSyncGameData.ts(44,51)`은
**`git stash`로 이번 수정 전에도 있던 것임을 확인**했다.

### 7. 실기기 확인 — 사용자 「실기기 확인됨」

세션 끝에 사용자가 **「실기기 확인됨」**이라고 알렸다. **항목별 보고도 문제 보고도 없었다** —
세션 40(아이콘)·41(연타 빗장) 때와 같은 형태다. 「다음 작업」 10번을 닫았다.

> **모달 구조를 바꿨는데 동작이 멀쩡하다는 것까지가 확인된 것이다.**

### 되돌리면 안 되는 것 (세션 38)

- **`animateSwipe`에 `'down'`을 되살리지 말 것.** 스와이프 학습완료 전용이었고 제스처는 없다.

  세션 36처럼 「죽은 코드인가 아닌가」를 또 판단해야 한다. 카드는 **카드네비로만** 넘긴다.

  레일은 래퍼 폭의 90%가 가운데 정렬이라 **5%에서 시작한다.** 셋 다 `railPercent()`
  (`시작 + 비율 × 폭`) 하나를 쓴다. 마커 `marginLeft`는 **`-마커폭/2`**여야
  「중심이 그 지점을 가리킨다」가 된다 (전에는 `-1`이라 4px 왼쪽이었다).
- **눈금 개수를 고정 숫자로 되돌리지 말 것.** `[0,1,2,3,4,5]`는 카드가 20장이어도 6개였다.
  **눈금 하나 = 카드 한 장**이고, 크기는 `getProgressTickSize()`가 레일 폭에서 정한다.
- **지나온 눈금 조건을 `i <= currentIndex`로 바꾸지 말 것.** 첫 카드에서 채움이 0인데
  눈금만 흰색이 되어 흰 레일 위에서 사라진다. `i < currentIndex`가 맞다.
- **마커 상자에 `overflow: 'hidden'`을 다시 넣지 말 것.** 상자 32px < 아이콘 36px이라
  좌우 2px씩 잘린다.

  테두리가 늘 자리를 차지해야 재생 강조가 켜질 때 **카드 크기가 흔들리지 않는다.**

- **완료화면에서 진행바·진행숫자를 다시 그리지 말 것.** `1 / 0`이 뜬다.

- **이력의 화면별 표를 누적으로 바꾸지 말 것.** `flashcards` 줄이 세션마다 늘어
  **안 본 32개가 파묻힌다.** 반대로 **세션 노트를 갱신으로 바꾸지 말 것** —
  같은 파일에서 두 번 다른 것이 나왔다는 사실이 사라진다.

### 되돌리면 안 되는 것 (세션 42)

- **익힘모달 배경으로 시트를 다시 감싸지 말 것.** `TouchableOpacity`·`Pressable`은
  `accessible`을 끄지 않는 한 **켜져 있고**(RN 0.86 `TouchableOpacity.js:303`),
  켜진 요소의 **자식은 한 덩어리로 묶인다.** 감싸면 닫기 버튼·완료 항목·「전체 다시 하기」에
  토크백 초점이 **따로 가지 않는다.** 배경은 **절대배치 형제**여야 한다.
- **`modalBackdrop`의 배경색을 `modalOverlay`로 되돌리지 말 것.** 칠하는 쪽이 그 색을 갖는다.
  `modalOverlay`는 이제 **자리만 잡는 상자**(`flex: 1` + `justifyContent: 'flex-end'`)다.
- **`completedCardImage`의 `gap`을 다시 `8`로 굳히지 말 것.** `LAYOUT.spacingSM`은
  폰에서 8이라 **폰 화면은 종전과 같고**, 태블릿에서만 10으로 벌어지는 것이 의도다.
- **`resetAnimation`을 `Animated.timing`으로 바꾸지 말 것.** 부르는 세 자리 모두
  **카드가 이미 밖으로 나가고 내용이 다음 카드로 바뀐 뒤**다. timing이면 새 카드가
  **밖에서 날아 들어온다.** 「부드럽게」라 적힌 옛 주석은 **코드와 반대였다.**
- **0-2절(보류)의 문구를 진단서로 믿지 말 것.** 세션 41이 「배경에 `Role`이 없다」로 적은 것은
  실제로는 **구조 문제**였다. 그 줄은 **어디를 볼지 가리키는 색인**이지 고칠 방법이 아니다.
