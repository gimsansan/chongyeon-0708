#### `services/audioCompat.ts` — `playToEnd()` 추가

`playAsync()`는 그대로 두고 새 메서드를 추가했습니다.

- `seekTo(0)` 후 재생하고 **`didJustFinish`가 올 때까지 await**
- 리스너는 `addListener`로 직접 붙여 `setOnPlaybackStatusUpdate`가 건 리스너를 뺏지 않음
- 종료 신호가 안 오는 경우 대비 타임아웃:
  - 시작 시 15초 상한 (로드 지연 커버)
  - 길이를 알게 되면 `남은 시간 + 800ms`로 재무장
  - **재생 위치가 실제로 전진했을 때만** 재무장 → 재생이 멈추면 마지막 타이머로 반드시 빠져나옴

#### 호출부

| 파일 | 이전 | 이후 |

| `matchGame.tsx` | `playAsync()` + 200ms 고정 딜레이 | `playToEnd()` + `SOUND_GAP_MS = 500` |

### 2026-08-14 (세션 2, 이어서) — 2번 전부 철회

#### 왜

동물게임에서 소리가 겹쳐 들리는 것은 **의도된 훈련 설계**입니다.
여러 동물 소리가 동시에 들리는 상황에서 무엇이 섞여 있었는지 분해해 알아내는 청각 훈련이고,
소리를 하나씩 들려주면 훈련이 성립하지 않습니다.
리뷰(`audio-review.md` 3번)에서 이것을 "순차 재생 버그"로 진단한 것이 틀렸습니다.

#### 되돌린 파일

| 파일 | 결과 |

| `services/audioCompat.ts` | `playToEnd()` 삭제 → 커밋 상태와 동일 |
| `matchGame.tsx` | `playAsync()` + 200ms 복원 → 커밋 상태와 동일 |
| `orderGame.tsx` | `playAsync()` + 1300ms 복원 → 커밋 상태와 동일 |

간격 값 200ms / 1300ms는 훈련 난이도를 정하는 설계값이므로 **손대지 않습니다.**
(사용자 지시로 이 숫자에 설명 주석도 달지 않았습니다.)

#### `hooks/useWordAudioPlayer.ts` — 내부 재작성

공개 API(`playWordSound` / `stopSound` / `isPlaying` / `progress`)는 **그대로**라 호출부는 수정하지 않았습니다.
`audioCompat` 대신 expo-audio를 직접 씁니다 (피아노·기타와 같은 방식).

| | 이전 | 이후 |
|---|---|---|
| 오디오 세션 | 재생마다 `setAudioModeAsync` | 훅 마운트 시 1회 |
| 플레이어 | 재생마다 `createAsync` → `unloadAsync` | 모듈 단위 LRU 캐시 8개 상주 |
| 이전 재생 중단 | `unloadAsync()` + 50ms 대기 | `pause()` (캐시 유지, 대기 없음) |
| 중복 호출 판정 | `if (isPlaying)` — state 클로저라 stale | `playbackIdRef` + ref 기반 중단 |
| 백업 타이머 | 3초 고정 | 소리 길이 + 500ms (길이 모르면 3초, 재생 진행 시 갱신) |
| 되감기 | 항상 새로 만듦 | `currentTime > 0`일 때만 `seekTo(0)` |

캐시를 **모듈 단위**에 둔 이유: 훅 내부(`useRef`)에 두면 화면을 나갔다 들어올 때마다 비워지고,
두 탭이 같은 단어 파일을 쓰는데도 캐시를 공유하지 못합니다.
LRU 축출 시 **재생 중인 플레이어는 건너뜁니다** (소리가 끊기지 않도록).

### 2026-08-15 — 4번을 4-A / 4-B로 분리, 5번 추가

#### 먼저: `interruptionMode`는 **탭끼리가 아니라 바깥 앱과의 관계**입니다

이번 세션에서 오해가 있었던 지점이라 적어 둡니다.

`setAudioModeAsync`의 `interruptionMode`는 **다른 앱**(유튜브·음악 앱 등)의 소리를
어떻게 할지 정하는 전역 설정입니다. **앱 안의 탭끼리와는 무관합니다.**

| 설정 | 다른 앱 소리 | 우리 소리 |
|---|---|---|
| `mixWithOthers` | 그대로 남 | 위에 겹쳐서 남 |
| `duckOthers` | 작아짐 | 잘 들림 |
| `doNotMix` | **꺼짐** | 혼자 남 |

앱 안의 소리끼리는 이 설정과 무관하게 항상 같이 납니다.
"탭을 바꾸면 그 탭 소리만 나야 한다"는 **4-A(재생 정지)** 가 담당하는 별개 문제입니다.

#### 사용자 결정 (2026-08-15)

> **훈련 중 다른 앱 소리는 차단해도 된다.**

따라서 4-B의 목표는 리뷰가 제안한 `mixWithOthers` 통일이 **아니라 `doNotMix` 통일**입니다.
청각 훈련 중 바깥 소리가 섞이면 훈련이 오염되고 측정값도 신뢰할 수 없기 때문입니다.
이 결정으로 동물게임의 `duckOthers`가 의도였는지 여부는 **더 확인할 필요가 없어졌습니다** — 어차피 `doNotMix`로 덮습니다.

### 2026-08-15 (세션 5, 이어서) — matchGame 카드 선택 지연 제거 (리뷰 항목 아님)

`handleButtonPress`의 가드가 **어느 카드든 애니메이션 중이면 전부 차단**하고 있었습니다.

### 2026-08-15 (세션 5, 이어서) — refri-test 문제음 누락 수정

> "20개 문항 중 2~3개 정도가 아예 재생이 안들렸다."

#### 진단 과정 (처음에 틀렸습니다)

첫 보고("어느 시점에서 재생이 아예 안 들림")를 **"한 번 실패하면 영구 침묵"**으로 읽고
예외 처리 구조를 고쳤습니다. 그런데 실제 증상은 **31문항 중 2~3개가 무작위로 빠지는 간헐적 누락**이었고,
진단이 틀렸습니다. 증상을 정확히 듣기 전에 원인을 단정한 것입니다.

#### 원인 — 재생마다 플레이어를 만들고 버리는 구조

```js
soundRef.current.remove();                     // 앞 플레이어 파괴
const player = createAudioPlayer(item.sound);  // 동시에 새 플레이어 생성
player.play();                                 // 로드도 안 끝났는데 재생 지시
```

앞 플레이어를 네이티브에서 정리하는 도중에 새 플레이어가 재생을 시작합니다.
대부분은 이기지만 **가끔 진다** — 무작위 누락의 양상과 맞습니다.

**이 앱은 같은 문제를 이미 두 번 이 방식으로 고쳤습니다** — 1번(드럼 풀)·3번(단어 캐시).
냉장고만 재생마다 만들고 버리는 구조로 남아 있었습니다. 5번 이전부터 있던 구조입니다.

#### 고친 것 — 상주 플레이어 하나를 재사용

```js
const player = ensurePlayer();     // 화면당 1개. 처음 쓸 때만 만든다
player.replace(item.sound);        // 음원만 갈아끼운다
player.play();
```

31문항을 돌아도 네이티브 플레이어는 **1개**입니다. 파괴와 생성이 겹치는 상황 자체가 없어집니다.
재생 순서·다시 듣기·정답 후 다음 문제·탭 이탈 시 정지는 손대지 않았습니다.

곁들여 고친 것:
- 언마운트 클린업에서 `remove()` 후 `soundRef`를 `null`로. 해제한 플레이어를 계속 붙들면 다음 재생 때 죽은 플레이어를 건드립니다.
- **포커스 가드에 걸려 재생을 건너뛸 때 로그를 남깁니다.** 조용히 return하면 원인을 찾을 수 없습니다.
  탭을 떠난 동안에만 찍히므로 평소에는 나오지 않습니다.

**실기기 확인 완료 — 누락이 사라졌습니다.**

#### `doNotMix`가 각 화면에 미치는 영향

앱 **안**의 소리끼리는 영향이 없습니다. 동물게임에서 소리 3개가 겹쳐 나는 것도 **그대로 유지됩니다**
(2번에서 확인된 훈련 설계). 바뀌는 것은 바깥 앱과의 관계뿐입니다.

| | 지금 | `doNotMix` 이후 |
|---|---|---|
| 바깥 앱 소리 (유튜브 등) | 그대로 나거나(`mixWithOthers`) 작아짐(`duckOthers`) | **멈춤** |
| 우리 앱 소리끼리 | 겹쳐서 남 | **그대로 겹쳐서 남** |
| 화면 진입 시 세션 재설정 지연 | 있음 (동물게임은 시작 버튼 뒤 `await`) | 없음 |
| 게임 이탈 후 설정 잔류 | `duckOthers`가 앱 전체에 남음 | 바꾸는 사람이 없어 잔류 없음 |

#### 4-B 실기기 확인 항목 (⚠️ 부작용 확인 포함)

1. **다른 앱 음악을 틀어놓고** 앱을 켠다 → 우리 앱이 소리를 낼 때 바깥 음악이 **멈추는지**
2. ⚠️ **앱을 끄거나 백그라운드로 보낸 뒤, 멈췄던 바깥 음악이 자동으로 다시 재생되는지.**
   `doNotMix`는 다른 앱 소리를 중단시키고 **자동 복구를 보장하지 않습니다** (OS·상대 앱에 따라 다름).
   사용자가 음악을 직접 다시 틀어야 한다면, 훈련 앱으로서 감수할지 판단이 필요합니다.
   → 감수하지 못할 경우의 대안: 앱 시작 시가 아니라 **훈련 재생 직전에만** `doNotMix`로 올리고
   화면을 벗어날 때 `mixWithOthers`로 되돌리는 방식. 다만 지연이 다시 붙으므로 최후 수단입니다.
3. 전화·알람이 온 뒤 끊었을 때 앱 소리가 정상 복귀하는지 (세션을 1회만 설정하므로 인터럽션 복구 확인 필요)
4. 각 탭(드럼·단어·피아노·기타·동물게임·냉장고)에서 소리가 **정상적으로 나는지** — 화면별 `setAudioModeAsync` 6곳을 제거하므로 누락된 곳이 없는지 전수 확인
5. 동물게임에서 **소리 3개가 여전히 겹쳐 나는지** (훈련 설계가 유지됐는지 확인)
6. iOS 무음 스위치 ON 상태에서도 소리가 나는지 (`playsInSilentMode` 유지 확인)
