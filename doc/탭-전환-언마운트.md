# 탭을 바꿔도 화면은 안 닫힌다

**개념 메모다.** 세션 69를 보면서 반복해서 놓친 자리만 적는다.
그 수정의 이전/이후는 [`doc/learn-탭이탈-타이머.md`](./learn-탭이탈-타이머.md)가 갖는다.

---

## 놓친 한 줄

`clearNextRoundTimer`가 탭 전환에서 **실패한 것이 아니다.**
언마운트 클린업이 **호출되지 않은 것**이다. 함수는 멀쩡하고, **부르는 문이 안 열린다.**

---

## 세 가지를 갈라 둔다

같은 말로 들리면 틀린다. 하는 일이 다르다.

| 이름 | 무엇인가 | 언제 도나 |
|---|---|---|
| `clearNextRoundTimer` | 타이머 id로 `clearTimeout` 하는 **함수** | **누군가 부를 때**만 |
| 언마운트 클린업 | `useEffect`가 돌려주는 `return () => { ... }` | 컴포넌트가 **사라질 때** |
| 블러 | `useStopAudioOnBlur` (포커스를 잃음) | 탭을 **떠날 때** |

클린업은 함수가 아니다. **문을 여는 타이밍**이다.
그 문 안에서 `clearNextRoundTimer`를 부를 뿐이다.

```
언마운트 클린업          블러(포커스 잃음)
      │                        │
      └── clearNextRoundTimer ─┘
              (같은 함수)
```

---

## 흔한 오해 → 사실

| 오해 | 사실 |
|---|---|
| 탭을 바꾸면 화면이 닫힌다 | 이 앱은 **안 닫힌다.** 숨길 뿐이다 |
| 화면이 닫힐 때 정리 = `clearNextRoundTimer` | 정리는 **클린업이라는 타이밍**이다. 함수는 그 안에서 불린다 |
| 클린업이 도는데 함수가 안 먹어서 블러에서 또 부른다 | 탭 전환에서 클린업 **자체가 안 돈다.** 그래서 블러에서 같은 함수를 부른다 |
| 모든 앱이 그렇다 | React Navigation 탭의 **기본값**이다. `unmountOnBlur`를 켜면 나갈 때 언마운트된다 |

---

## 왜 탭을 바꿔도 안 닫히나

이 앱의 `Tabs`는 `unmountOnBlur`를 쓰지 않는다.
한 번 연 탭은 **마운트된 채** 남고, 다른 탭을 올리면 가려질 뿐이다.

```
처음 learn을 연다     →  마운트 (생긴다)
피아노로 간다         →  learn은 그대로 살아 있다  ← 여기선 클린업 없음
앱을 완전히 내린다    →  그때 언마운트 (사라진다)  ← 여기선 클린업 있음
```

`useEffect` 클린업은 「사라질 때」만 돈다.
살아 있는 화면을 가리는 것은 「사라짐」이 아니다.

```ts
useEffect(() => {
  return () => {
    clearNextRoundTimer();  // 이 줄이 나쁜 게 아니다
  };                        // 탭 전환에서는 이 return이 실행되지 않는다
}, [clearNextRoundTimer]);
```

---

## 그래서 블러에서 같은 함수를 부른다

떠나는 길이 둘이다. 정리해야 하는 것은 하나다.

```
떠나기 A — 정말 사라짐     →  언마운트 클린업  →  clearNextRoundTimer
떠나기 B — 탭만 바꿈       →  클린업 안 돔    →  블러에서 clearNextRoundTimer
```

B를 안 넣으면 600ms 예약이 learn 안에 살아 남아, 다른 탭에서 다음 문제가 혼자 준비된다.

---

## 이 앱에서만 사실인가

| | |
|---|---|
| 이 앱 | 사실. 탭 기본값을 그대로 쓴다 |
| React Navigation / Expo Router 탭 | 기본이 같다. `unmountOnBlur: true`면 나간다 |
| 스택 화면을 pop | 보통 언마운트된다. 그때는 클린업이 돈다 |

「탭 = 언마운트 안 됨」은 **이 네비게이터의 기본값**이지, 화면이 바뀌는 모든 경우의 법칙이 아니다.
