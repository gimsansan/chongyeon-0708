## 세션 62 — learn 액션줄 (중단된 구현 이어받기 · 점검 6건 → 고침 0)

지시는 **「@doc/handoff11.md 중단된 작업이 있어 이어서 해줘」** 하나였다.

### 중단된 자리는 인계문이 아니라 `git log`가 답했다

인계문에는 이 일이 **없었다** — 열려 있던 것은 실기기 확인뿐이었다.
HEAD가 인계문의 마지막 커밋(`f629997`)이 아니라 **사용자 커밋 `cd0a017`**이었고,
거기에 새 설계 `doc/learn-액션줄.md`와 `constants/layout.ts` 토큰 여섯이 들어와 있었다.
그 토큰이 쓰는 **`scaleActionByWidth`가 정의되지 않아 저장소가 컴파일되지 않았다**(`tsc` 6건).

> **인계문은 내가 쓴 것까지만 안다.** 사용자가 그 뒤에 커밋한 것은 거기 없다 —
> **「이어서」는 `git log -1`과 `tsc`부터**다. 규칙 2-3의 3번(「관련 코드를 읽어
> 현재 상태가 인계문과 일치하는지」)이 이 자리를 위한 것이다.

### 방향이 61에서 뒤집혔다

61은 **「바닥에 두고 칸을 맞춘다」**(`flex: 1` · 64 반환)였고,
62는 **「바닥에서 뺀다」**다. 시작·다시 듣기를 난이도 아래 **액션줄**로 올려
탭바 근처에서 아예 치웠다. 설계 문서도 그렇게 적고 있다 — 「이번은 그 전환이다」.

| 파일 | 무엇을 |
|---|---|
| `app/(tabs)/learn/index.tsx` | `quitRow` → **액션줄**(`space-between`). 왼쪽은 **칸 하나**이고 상태가 라벨·아이콘·동작을 바꾼다. 왼쪽이 비면 **빈 `View`**를 남긴다 |
| `components/game/WordGame.tsx` | 바닥 버튼 둘 · 래퍼 둘(`readyActionWrapper`·`replayWrapper`) · 초록 알약 스타일 셋 제거. `WordGameRef`에 `start`·`replay`, `onProgressChange`에 `isPlaying` |
| `constants/layout.ts` | `scaleActionByWidth(하한, 상한, 폭비율)` 정의. `startOffsetY`·`replayOffsetY`를 **타입·함수에서 제거** |
| `constants/colors.ts` | `playingBlue`(#4da8de) — `WordGame`에 리터럴이던 값 그대로다 |

- **본문은 한 줄도 안 옮겼다.** `handleStartGame`·`handleReplaySound`는 `WordGame`에 그대로 있고
  부모가 ref로 부른다 — 세션 60의 **「버튼은 부모, 하는 일은 자식」과 같은 골격**이다.
- **왼쪽 라벨·아이콘·동작은 종전 그대로다.** 색도 리터럴을 토큰으로 옮겼을 뿐 값이 같다.
  설계의 「기능·문구·아이콘을 새로 만들지 않는다 (자리만 옮긴다)」를 지켰다.
- `numberOfLines={1}`은 **점검 발견이 아니라 설계 이행**이다 — 「한 줄이 두 줄로 접히지
  않게 한다」가 설계에 적혀 있다. `GameExitButton`(61)과 같은 처리다.

### 점검 6건은 **전부 0-2절로 갔다**

🔧 다섯(**부모 상태가 한 프레임 늦다** · 로딩 중에도 「시작하기」가 눌린다 ·

> **여섯째 줄은 61과 갈린 자리다.** 흰 알약의 테두리를 게임 「나가기」에서는

> **같은 모양의 부품이 두 기준을 갖고 있다.**

## 세션 63 — 냉장고 다시 듣기가 카드와 겹치던 것 (점검 3건 → 고침 0)

**사용자가 먼저 고쳤다.** 실기기(Note10+)에서 플로팅 「다시 듣기」가 2행 가운데 카드와
겹쳤고, `bottom`에서 `insets.bottom`을 빼고 `refriFloatingReplayBottom`
(`(선반 아래 패딩 − 버튼) / 2` — 폰 18 · 태블릿 12) 토큰으로 바꿔 뒀다.
설계 원문은 사용자가 쓴 `doc/냉장고-다시듣기-위치.md`다.

지시는 **「교차검증만 해봐」**였다. **고치지 않고 계산만 했다.**

### 기준이 둘이었다

버튼의 `bottom`은 **화면 바닥** 기준인데 88(`refriTrayPaddingBottom`)은 **선반 안쪽** 값이다.
둘은 **선반 바닥이 화면 바닥에 닿을 때만** 같은 자리인데, 세로 스택(게이지·냉장고·선반)에
**`flex: 1`이 하나도 없어** 남는 높이가 선반 **아래**에 남는다.

| 기기(인셋 가정) | 스택 / 남은 칸 | 선반 아래 여유 |
|---|---|---|
| 411×868 (34/24) | 739 / 746 | **+7** — 실기기에서 「맞다」로 보인 이유 |
| 411×868 (34/0) | 739 / 770 | +31 |
| 360×800 (24/24) | 712 / 688 | −24 |
| 320×569 (24/0) | 577 / 481 | **−96** |
| 800×1280 태블릿 | 980 / 1192 | **+212** |

> **`insets.bottom` 제거 자체는 맞다** (0-2절 세션 47 · 근거는 53의 `BottomTabBar.js:248`).
> 갈린 것은 **뺄 값이 아니라 잴 자리**였다.

### 「선반 안으로 옮겨서 고쳐줘」 (`406cbb2`)

버튼을 `answersContainer`의 **자식**으로 옮겼다. 값(`refriFloatingReplayBottom`)은 그대로이고
**기준만** 바뀌었다 — 스택이 화면을 채우든 남든 버튼은 늘 그 88 칸 안이다.

- **Yoga는 절대배치 자식의 `bottom`에서 패딩을 빼지 않는다.** `AbsoluteLayout.cpp`가
  `측정높이 − 자식 − 테두리 − 마진 − bottom`이다 — **소스로 확인했다.** 반대였다면
  선반 안에 넣은 버튼이 88을 건너뛰어 **카드 위로 올라갔다.**
- 가로 가운데는 그대로다(선반이 화면 폭을 다 쓴다) · 버튼 `elevation: 4` > 카드 3이라
  이제 형제가 된 카드 위에 그려진다 · 동작·아이콘·비활성·시작 버튼은 안 건드렸다.

**점검 3건은 전부 0-2절로 갔다** — 📱 하나(**선반이 넘치면 버튼도 함께 넘친다**) ·
🔧 둘(zIndex 두 값이 부모-자식이 돼 비교가 뜻을 잃었다 · 88이 리터럴이라 태블릿에서 위아래 12뿐).
**사용자가 「1번은 64에서 거의 해소, 2·3은 급하지 않다」고 답했다.**
그 64~67이 아래 「다음 작업」 7번이다 — **냉장고가 남은 칸을 쓰게 되면서**
360×800·320×569는 계산상 들어온다.

> **1번은 맞바꾼 것이다.** 화면 기준일 때는 짧은 폰에서도 **보이긴 했다**(대신 겹쳤다).
> 선반을 따라가는 지금은 **선반이 넘치면 버튼도 넘는다.** 세션 61의
> 「하한을 걷는 것은 맞바꾸는 것이다」와 같은 모양이다.

### 문서는 **머리만** 고쳤다

지시가 「문서 머리만 「선반 기준」으로」였다. 제목·상태줄에 기준이 선반임을 적고,
아래 본문이 화면 바닥 기준으로 쓰였다는 단서 한 문단을 붙였다. **본문은 안 건드렸다** —
계산과 값이 그대로라 여전히 맞는다. **커밋하지 않았다**(사용자 문서).

## 화면 부위를 부르는 이름 — **원문은 [`handoff5.md`](./handoff5.md)**

flashcards 화면과 카드박스 안의 이름표·그림은 handoff5가 갖는다.
**익힘모달(`flashcards/index.tsx`) ≠ 미션모달(`components/MissionProgressIcon.tsx`) ≠ 이름모달.**

드럼 쪽 — 연주모드 / **듣기연습**(헤더 버튼) = 퀴즈모드(배지) · 캐릭터 · 마커 ·
하단 고정 ◀▶(↻) · 악기명 레이블 · 결과창.
**게임 넷(`new/(games)`)** — 오른쪽 아래 **「나가기」**(≠ 결과창의 **「홈으로」**,
≠ 우상단 **미션아이콘**). 「나가기」만 `_layout`이 그린다 — **화면 파일에는 없다.**

**냉장고(`refri-test`)** — 게이지 · 냉장고 씬(상자 포함) · **선반**(`answersContainer`,
아래를 88 비운다) · 그 칸 안의 **다시 듣기** · 시작 전에만 뜨는 **시작 버튼** ·
완료 오버레이. **다시 듣기와 시작 버튼은 함께 뜨지 않는다**(`isGameStarted`로 갈린다).

**learn 쪽이 세션 62에 바뀌었다.** 난이도 줄(연습·도전) 아래가 **액션줄**이고,
그 줄에 **왼쪽 토글**(시작하기 / 계속하기 / 다시 듣기 · 재생 중...)과
오른쪽 **「그만하기」**가 있다. 결과창 주 버튼은 **「확인」**이다(드럼은 「다시 하기」).

> **왼쪽 토글은 `learn/index.tsx`가 그린다.** `WordGame`을 아무리 읽어도 버튼이 안 나온다 —
> 61의 「나가기」와 같은 모양이다.

### 세션 62 주의사항 (learn 액션줄)

- **「이어서」는 인계문이 아니라 `git log -1`과 `tsc`부터 본다.** 인계문은 **내가 쓴 것까지만**
  안다 — 사용자가 그 뒤에 커밋한 것(설계 문서 · 반쯤 넣은 토큰)은 거기 없다.
  **저장소가 컴파일되지 않는 상태로 시작할 수 있다.**
- **버튼을 부모로 올리면 상태가 한 프레임 늦다.** 자식 → `onProgressChange` → 이펙트 →
  부모 `setState`라 **누른 프레임의 상태로 그려지지 않는다.** 「그만하기」 하나였을 때는
  표가 안 났고 **상태마다 바뀌는 토글에서 표가 난다.**
- **`space-between`은 자식이 하나면 그 하나를 왼쪽으로 보낸다.** 오른쪽 것을 오른쪽에
  두려면 **빈 `View`**를 왼쪽에 남긴다(또는 `marginLeft:'auto'`).
- **한 줄에 알약 둘이면 폭에서 역산한다.** 높이 비례로 잡으면 좁은 폰에서 줄이 접힌다.
  `numberOfLines={1}` + `flexShrink`로 **어느 쪽이 먼저 줄지도 정해 둔다** —
  줄이면 안 되는 쪽은 `flexShrink: 0`이다.
- **자리를 옮기면 그 값을 근거로 적힌 0-2절 줄이 전부 낡는다.** 대비·리터럴·접근성 줄은
  「어느 파일」이 근거의 절반이다. **62에 손본 일곱 줄 중 넷이 지난 세션 것이었다.**
- **없앤 메트릭은 타입에서도 뺀다.** `startOffsetY`·`replayOffsetY`를 `WordGameMetrics`에
  남기면 다음 세션이 「쓰는 곳이 있나」를 다시 센다 (61의 `contentMinHeight`와 같다).
- **같은 모양의 부품이 두 기준을 갖지 않게 한다.** 흰 알약 테두리가 게임 「나가기」는
  5.2:1, learn 「그만하기」는 1.23:1이다 — **한쪽만 고치면 이렇게 갈린다.**

### 세션 63 주의사항 (냉장고 다시 듣기)

- **뺄 값이 맞아도 잴 자리가 틀릴 수 있다.** `insets.bottom` 제거는 옳았는데
  **어디서부터 재는가**가 갈렸다. `bottom`은 화면 바닥, 88은 선반 안쪽 —
  **두 기준이 같아지는 조건**(선반 바닥 == 화면 바닥)을 아무도 보장하지 않았다.
- **세로 스택에 `flex: 1`이 없으면 남는 높이는 마지막 자식 「아래」에 남는다.**
  냉장고는 게이지(고정) · 씬(화면 40%) · 선반(내용)뿐이라 기기마다 그 여유가 다르다 —
  **411×868에서 +7이라 실기기 확인이 통과했다.** 한 기기에서 맞는 것과 기준이 맞는 것은 다르다.
- **Yoga는 절대배치 자식의 `bottom`에서 패딩을 빼지 않는다**(`AbsoluteLayout.cpp`:
  `측정높이 − 자식 − 테두리 − 마진 − bottom`). 그래서 **패딩 칸 안에 버튼을 앉힐 수 있다.**
  반대로 믿으면 88을 건너뛴다 — **추측하지 말고 소스를 볼 것.**
- **부모 안으로 들어가면 `zIndex` 비교가 뜻을 잃는다.** 형제였을 때의 두 토큰이
  이제 부모-자식이라 순서를 안 정한다. 정하는 것은 **형제 순서와 `elevation`**이다.
- **문서 둘을 스테이징할 때 사용자의 편집이 함께 담겼다.** `f535e60`이 그 자리다 —
  `점검표.md`·`점검-이력.md`에 사용자가 쓰던 **세션 63 노트**가 들어갔다.
  **파일 단위 `git add`도 「그 파일의 작업 트리 전부」다** (세션 59의 `-A` 사건과 같은 갈래).
  **고칠 파일을 스테이징하기 전에 `git status`로 남의 편집이 있는지 본다.**
- **사용자가 다른 창에서 같은 저장소를 만지고 있을 수 있다.** 63 뒤에 이력의
  64~66 노트가 **코드보다 먼저** 보였다. 그때 「코드가 없다」고 적었는데
  **잠시 뒤 들어왔다** — 내가 본 것은 **그 순간의 스냅샷**이다.
  **없다고 단정하기 전에 다시 보고, 인계문에 적을 때는 「그 시점」임을 밝힌다.**
- **사용자가 세션 번호를 이미 매겨 뒀을 수 있다.** 냉장고 노트가 **63**으로 적혀 있어
  거기 맞췄다. 내 번호를 우선하면 이력에 63이 둘이 된다.
