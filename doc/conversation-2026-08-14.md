## 13. Claude

네, 연타라고 할 수 없습니다. "다시 듣기"는 연주가 아니라 **같은 문제를 한 번 더 듣는 동작**이니까요.

다만 짚어주신 덕에 문제가 하나 보입니다. **코드 경로상으로는 이게 같은 악기를 반복 재생하는 유일한 통로입니다** (`drum/index.tsx:480`). 그리고 여기서는 제가 넣은 폴리포니가 **오히려 틀린 동작**입니다.

- 드럼 샘플이 0.5초이므로, ↻를 0.5초 안에 두 번 누르면 → `player.playing === true` → 임시 플레이어로 **겹쳐 재생**
- 결과: 같은 스네어가 두 겹으로 울려서 **"두 번 친 것처럼"** 들림
- 악기를 맞히는 퀴즈에서 이건 방해가 됩니다

다시 듣기의 올바른 동작은 겹치기가 아니라 **"끊고 처음부터 다시"** 입니다. 이전 코드가 (느리긴 해도) 이 부분은 오히려 맞게 하고 있었습니다.

정리하면 — 같은 `playSound` 하나로 두 가지 상반된 요구를 처리하려니 충돌합니다.

| 용도 | 필요한 동작 |
|---|---|
| 연주(드래그·순환 버튼) | 겹쳐 재생 |
| 퀴즈 다시 듣기 | 끊고 재시작 |

`replaySound()`를 따로 두거나 `playSound(key, source, { restart: true })` 옵션을 주면 됩니다. 고칠까요?

## 15. Claude

**폴리포니를 빼고 `playSound`를 항상 "끊고 처음부터"로 단순화하는 것**을 추천합니다.

이유는 간단합니다:

- 악기가 **서로 다르면** 어차피 각자 플레이어가 있어서 겹쳐 납니다 (드래그·순환 버튼은 여기 해당)
- 같은 악기가 겹치는 경우는 **↻ 다시 듣기 하나뿐**인데, 거기선 겹치는 게 틀린 동작

즉 지금 UI에서 폴리포니는 **쓸모는 0, 해로움은 1**입니다. 제가 넣은 오버플로 분기를 지우면 코드도 짧아지고 `OVERFLOW_RELEASE_MS`·임시 플레이어 관리·언마운트 정리가 통째로 사라집니다.

```ts
const playSound = useCallback((soundKey, source) => {
  const player = getPlayer(soundKey, source);
  player.seekTo(0).catch(() => {});
  player.play();   // 재생 중이어도 처음부터 다시
}, [getPlayer]);
```

나중에 마커 탭으로 드럼패드를 만들면 그때 폴리포니를 다시 넣으면 됩니다. 지금 미리 넣어두는 건 검증 안 된 죽은 코드일 뿐입니다.

const player = getPlayer(soundKey, source);
