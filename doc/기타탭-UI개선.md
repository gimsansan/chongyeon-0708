선언만 되어 있고 아무 데서도 쓰이지 않던 `activeNotes` state를 실제로 연결했다.

- 누른 칸이 `FRET_FLASH_MS`(260ms) 동안 앰버(`#d4a373`)로 밝아지고 글자가 어두워진다 (`fretActive` / `fretTextActive`).

- 같은 음을 연타하면 앞 타이머를 취소하고 다시 건다. 언마운트 시 남은 타이머를 모두 정리해 해제 뒤 `setState`가 불리지 않게 했다.

## 4. 레이아웃 / 겹침

- **`SafeAreaView` → `View` + `useSafeAreaInsets`.** 가로 모드에서 노치·제스처바가 좌우로 오므로 컨테이너에 `paddingLeft/Right = insets.left/right`를 준다.
- **미션 `?` 아이콘 이중 absolute 제거.** `MissionProgressIcon`은 자체적으로 `position: absolute`인데 그걸 다시 absolute 래퍼(`missionWrapper`)로 감싸고 있어 좌표가 겹쳐 밀렸다. 래퍼를 없애고 피아노(`MusicTrainingScreen`)와 같이 `style` prop으로 위치만 넘긴다.
- **아이콘과 지판 겹침 해소.** 아이콘이 1번줄 마지막 칸(G4) 위에 올라와서, 지판 오른쪽에 `MISSION_ICON_CLEARANCE`(52 = 아이콘 32 + 좌우 패딩 8씩 + 여유)만큼 자리를 비웠다.
- **로딩 화면.** 맨 `ActivityIndicator` → 갈색 배경(`#1a120b`) + 앰버 인디케이터. 진입 시 흰 화면이 번쩍이지 않는다.

## 6. 훈련 중 피드백이 안 보이던 문제 (같은 날 후속 수정)

> **부르는 이름: "기타 좌측 패널 세로 배치."** 6항(피드백 잘림)과 6-1항(패널 압축 모드)을 묶은 말이다.
> 세부만 가리킬 때는 "기타 피드백 잘림" / "기타 패널 압축 모드".
> 코드 표식은 `feedbackSlot` · `diffSection` · `COMPACT_PANEL_HEIGHT` · `isCompactPanel`.

증상: **훈련 모드에서 피드백 문구가 한 번도 보이지 않는다.** 피드백은 훈련 중에만 채워지므로 사실상 항상 안 보였다.

원인은 상태나 조건부 렌더링이 아니라 **좌측 패널 높이**였다.

- 기타 탭은 피아노(`app/(tabs)/_layout.tsx`의 `activity`, `tabBarStyle: { display: 'none' }`)와 달리 하단 탭바를 그대로 둔다. 화면 세로가 `64 + insets.bottom`만큼 줄어 2280×1080 기기에서 패널에 쓸 수 있는 높이는 **약 327dp**다.
- 훈련을 켜면 '다시 듣기' 버튼이 끼어들어 패널 내용이 **약 386dp**가 됐다 (패딩 24 + SCORE 67 + 훈련 버튼 48 + 다시 듣기 42 + 난이도 163 + 피드백 42).
- `feedbackSlot`은 마지막 자식이고 `marginTop:'auto'`였는데, **남는 공간이 없으면 auto 마진은 0으로 접힌다.** 그래서 피드백 칸이 패널 아래 경계 밖으로 밀려 잘렸다. 훈련 전에도 여유가 약 29dp뿐이라 이미 모자란 상태였다.

고친 방식 — 세로 고정비를 줄이고, **늘고 주는 칸을 난이도 목록 하나로 몰았다.**

| 항목 | 이전 | 이후 |
|---|---|---|
| 패널 `paddingVertical` | 12 | 8 |
| SCORE 카드 | `paddingVertical 6`, 숫자 26/30, `marginBottom 10` | `paddingVertical 4`, 숫자 22/26, `marginBottom 8` |
| 훈련 시작/종료 | `paddingVertical 11`, `marginBottom 8` | `paddingVertical 9`, `marginBottom 6` |
| 다시 듣기 | `paddingVertical 9`, `marginBottom 8` | `paddingVertical 7`, `marginBottom 6` |
| 난이도 영역 | 내용 높이 그대로 | `flex: 1, minHeight: 0` — 남는 세로를 여기가 먹고, 모자라면 여기가 준다 |
| 난이도 버튼 | 고정 높이(`paddingVertical 7`), 간격 5 | `flex: 1, maxHeight: 40`, `paddingVertical 5`, 간격 4 — 4칸이 목록 높이를 나눠 갖는다 |
| 피드백 칸 | `marginTop: 'auto'`, `minHeight 42` | auto 마진 제거, `minHeight 38` |

결과(같은 기기 기준): 훈련 중에도 피드백 38dp가 항상 확보되고, 난이도 버튼은 남는 높이에 따라 27~36dp로 조절된다. 로직은 건드리지 않았다 — 스타일과 주석만 바뀌었다.

### 6-1. 작은 기기 대응 (압축 모드)

위 구조로 **피드백이 잘리는 일은 크기와 무관하게 없어졌다.** 사이드바에서 늘고 주는 항목은
`diffSection`(flex: 1) 하나뿐이고 나머지는 RN 기본값대로 `flexShrink: 0`이라, 세로가 모자라면
난이도 영역이 먼저 줄고 피드백 칸은 마지막까지 남는다.

다만 난이도 버튼 높이가 `(패널 높이 − 219) / 4`로 정해져 **하한이 없었다.** 작은 기기에서는
글자가 눌린다. 그래서 패널 높이를 `onLayout`으로 **측정**해 `COMPACT_PANEL_HEIGHT`(320dp)
미만이면 압축 모드를 켠다 — 패널 패딩 8→6, SCORE 패딩 4→2·숫자 22→18·아래 여백 8→4,
훈련 버튼 9→7·6→4, 다시 듣기 7→6·6→4, 피드백 칸 38→34. 합쳐 **약 31dp**를 난이도 4칸에 넘긴다.

`windowHeight − 탭바(64 + insets.bottom)`로 계산하지 않고 측정한 이유는, 그러면
`app/(tabs)/_layout.tsx`의 탭바 높이를 이 파일에 베껴 두게 되기 때문이다. 압축 여부는 패널
높이에 영향을 주지 않으므로(높이는 부모가 정한다) 측정 → 재렌더가 되풀이되지 않는다.

난이도 버튼 높이 (훈련 중, 4칸 기준):

| 가로 시 화면 세로 | 6항 직후 | 압축 모드 적용 후 |
|---|---|---|
| 320dp (iPhone SE 1세대급) | 9dp — 글자 잘림 | 17dp — 압축 켜짐, 아슬아슬 |
| 360dp (구형 보급형 안드로이드) | 19dp | 27dp — 압축 켜짐 |
| 375dp (iPhone SE 2/3) | 18dp | 25dp — 압축 켜짐 |
| 393dp (검증 기기, 2280×1080) | 27dp | 27dp — 압축 꺼짐, 변화 없음 |
| 태블릿 (800dp) | 40dp 상한 | 40dp 상한, 남는 세로는 난이도 목록 아래 빈 자리 |

**남은 한계:** 320dp급(가로 세로 320dp) 초소형 구형 기기는 압축을 켜도 17dp라 여전히 빠듯하다.
이보다 더 줄이려면 SCORE 카드를 접거나 패널을 스크롤로 바꿔야 하는데, 대상 기기가 아니라고
보고 넣지 않았다. 또 시스템 글꼴 크기를 크게 키운 경우(접근성)는 고정 항목들이 함께 커지므로
같은 압박을 받는다 — 프로젝트 전체가 `maxFontSizeMultiplier`를 쓰지 않아 여기서만 넣지 않았다.

## UI 외 변경 (같은 작업 중 별도 요청으로 반영)

디자인 범위 밖이지만 함께 고친 것들이다.

1. **미션 모달의 '현재 진행 상황'에 클리어 표시 추가.**
   `1단계 (★)` → `1단계 (★, ✓)`, 값도 피아노와 같은 문구(`누적 N회 / 최고 N점`)로 맞췄다. 인라인 매핑을 `progressItems` 상수로 분리.

2. **별 획득 조건을 모달 안내와 일치시킴.**
   모달은 "난이도별 누적 3회 성공"이라고 안내하는데 코드는 정답 1회마다 `addStar`를 불러 **첫 정답에 바로 별이 붙었다.** 피아노와 동일하게 `if (newCumulativeSuccesses >= 3)`로 감쌌다.
   ※ 이미 첫 정답으로 별을 받아 둔 기기는 `AsyncStorage`에 값이 남아 있어 그대로다. 모달의 ↻(초기화)를 한 번 눌러야 새 조건으로 확인된다.
