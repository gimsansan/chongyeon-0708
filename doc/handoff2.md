### 3. 미션 아이콘 색 (`7f25391`)

사용자가 "누적 3회인데 아이콘 색이 안 바뀐다"고 해서 확인한 데서 나왔다. **둘 다 문제였다.**

**색이 안 보였다.** 별을 얻어도 `#a0a0a0` → `#c0c0c0`, 회색에서 회색이었다.
**문턱도 높았다.** 피아노는 `levels.every(...)`라 **다섯 난이도를 전부** 채워야 바뀌어서,
1~4단계를 채우는 동안 아무 변화가 없었다.

고친 방식은 **밝기가 아니라 색상(hue)으로 가르는 것**이다.

| 상태 | 색 |
|---|---|
| 아무것도 없음 | `#a0a0a0` 회색 (그대로) |
| **별 하나라도** 얻음 | **`#CD7F32` 브론즈** |
| 전부 클리어 | `#FFD700` 금색 (그대로) |

모달 안의 `★`·`✓`는 예전 기준(전부 달성) 그대로다.

### 4. 기타 아이콘이 영영 회색이던 버그 (`7f25391`)

**그 키는 아무도 쓰지 않는다.** 그래서 기타는 무엇을 해도 회색이었다.

### 1. 오버레이가 인셋을 안 본다 (`ab37121`) — 세션 28 「다음 작업」 2번

두 오버레이(미션 성공 · 낙하 카운트다운)는 `midgroundLayer`의 **형제**라

```js

  ...safeAreaFrameStyle,          // 제어반이 쓰는 바로 그 프레임

};
```

스타일시트의 `top: 0 / left: 0 / right: 0`은 뺐다. **위치는 이제 렌더 한 곳에서만 나온다.**

**인계문이 적어둔 `bottom`만 고치지 않았다.** 두 화면은 가로모드라
큰 인셋은 `insets.bottom`이 아니라 **`insets.left`/`right`(노치·제스처)**다.

| bottom만 고쳤다면 | 남는 어긋남 |
|---|---|
| 낙하 카운트다운 | 숫자가 노치 쪽으로 **`insets.left / 2`만큼 밀린 채** — 연주 영역 한가운데가 아니다 |
| 미션 성공 오버레이 | 인셋 바깥 여백까지 덮는다 |

즉 **실제로 어긋나는 축을 그대로 두는 수정**이 된다. 원인이 같아서 네 변을 함께 맞췄다.

**커밋 없이 끝난 세션이다.** 결과물은 세션 31이 커밋했다(`56c0984` · `3a872a2`).

드럼 연주 화면의 **악기명 레이블을 위로 올리고 싶다**는 요청에서 시작했다.
`currentInstrumentDisplay`의 `top`을 음수로 주자 **레이블이 사라지고 그 자리에
배경 이미지(`drum_m.webp`)가 보였다.** z-index 문제가 아니라 **잘린 것**이다 —
`position: absolute`라 `top`이 음수면 부모 밖으로 나가고, Android는 View overflow
기본이 `hidden`이라 그 부분이 그려지지 않는다.

그래서 `container`에 `paddingTop: 72`를 줘 부모 안에 여백을 만들고 레이블을 거기 두었다.
**잘림은 막았지만 드럼 세트가 함께 내려가는 부작용이 있다.** 세션 31에서 되돌렸다.

### 1. 레이블을 ScrollView 밖으로 (`2b6c34c`)

사용자가 다른 도구에서 받은 플랜을 가져와 **교차검증**을 요청했다.
플랜의 방향(ScrollView 밖으로 빼기)은 맞았고, 결정적인 근거는 **이 화면이 같은 문제를
이미 같은 방식으로 한 번 풀었다**는 것이다 — 캐릭터·순환 버튼이 이미 ScrollView 밖
`drumOverlayFixed` 오버레이로 그려지고 있다.

왜 `top`만으로 안 되는지도 확인했다. `horizontalScrollContainer`가 `flex: 1`이지만
부모 체인이 콘텐츠 크기라 **`container` 높이가 사실상 드럼 세트 높이**다.
즉 `top: 0`이 이미 드럼 세트 꼭대기이고, 더 올릴 여지가 없다.

**플랜대로 붙였으면 버그가 났다.** 그 지점이 이 세션의 핵심이다:

| 플랜이 놓친 것 | 결과 |
|---|---|
| `InteractiveDrumSet`이 **넷**이다 (FlatList 2·3·4·5악기 페이지) | 상태를 하나만 두면 **페이지를 넘겨도 이전 페이지 악기명이 남는다** |
| 부모에 `currentInstrument`가 **이미 있다** (`:204`, 퀴즈 정답 악기) | 이름 충돌 |
| `onInstrumentChange`가 자식 `useEffect`의 **의존성**이다 | 부모가 setState하는 순간 매 렌더 effect 재실행 |

`removeClippedSubviews`가 없어 페이지 4개가 전부 살아 있으므로, 넘어간 페이지가
상태를 지워주지도 않는다. 그래서 **페이지 인덱스를 함께 올려보내고 배열에 담는다.**

```js
onInstrumentChange(instrument, pageIndex)   // 스크롤러가 index를 붙여 중계
const labelInstrument = instrumentByPage[currentDrumScrollIndex] ?? null;
```

세 번째 항목은 `useCallback` 규율에 맡기지 않고 **자식 쪽에서 막았다.**
콜백을 ref에 담아 effect 의존성에서 뺐다 — 부모가 어떤 함수를 넘기든
알림은 `currentInstrument`가 실제로 바뀔 때만 나간다.

곁들여 정리한 것:

- `instrumentLabelVisible` 제거. `currentInstrument`와 **항상 같이 켜지고 꺼져서**
  (`snapToInstrument`, 마커 `onPress`, `moveToNeutralPosition`) 중복이었다
- `hideCurrentInstrumentLabel` prop 제거 — 레이블이 자식에 없으니 죽은 prop이다.
  `InteractiveDrumSet`은 이 화면에서만 쓰인다(전수 확인)
- 폭 `Math.max(140, drumSetSize * 0.11)` + `left: '50%'` + `translateX` 절반 밀기 →
  `alignItems: 'center'`. 사실상 항상 140이던 고정폭이었고, 이제 글자 길이·화면 폭을 안 탄다
- 세로 위치는 `headerHeight`(실측) + 화면 높이 비례 간격(8~24 클램프). 고정 px이 아니다

`npx tsc --noEmit` 새 오류 0건. 남은 `hooks/useSyncGameData.ts(44,51)`은
세션 29에서 이미 무관한 기존 항목으로 확인된 것이다.

그림은 넷 다 캔버스 세로 **중앙**에 있다(중심 y ≈ 49.9%). 그런데 드럼은 바닥에 놓인

같은 기준으로 다시 뽑아야 한다. 악기 좌표를 아트워크에 손으로 맞춰온 기존 관행과도 코드 쪽이 맞다.

- `DrumLayout`에 **`bottomAlignOffset`** 추가 (3악기 `0`이 기준). 원시 픽셀을 `80 / 540`

- `InteractiveDrumSet`의 `drumSetContainer`에 **`translateY`**로 적용

**`padding`·`margin`이 아니라 `transform`인 이유**가 핵심이다. 이 컨테이너는 ScrollView
안에 있고 콘텐츠가 **화면에 들어가면 가운데, 넘치면 위로** 정렬된다. 레이아웃을 건드리면
콘텐츠 높이가 같이 늘어, 실제로 내려가는 양이 **가운데 정렬일 때 절반 · 위 정렬일 때 전부**가
된다. 즉 작은 폰과 태블릿이 서로 다르게 움직인다 (규칙 3). `transform`은 그리기만 옮긴다.

### 2. 세트를 내리자 캐릭터만 어긋났다 (같은 커밋)

고정으로** 그리는 것이라 세트를 따라 내려가지 않는다. 캐릭터만 따라 내려가 버튼 줄에서 벗어났다.

그래서 **초기 위치에서만 보정을 도로 뺐다.** 악기로 스냅할 때의 좌표는 그림 기준이라
보정을 **유지**한다 — 컨테이너가 내려간 만큼 캐릭터도 내려가야 드럼 위에 앉는다.

| 페이지 | 캐릭터가 올라간 양 (`drumSetSize` 324 기준) |

| 2악기 | **48px** ← 사용자가 지적한 것 |

### 3. 악기명 레이블을 제 높이만큼 아래로 (`092d102`)

```
top: headerHeight + instrumentLabelGap + instrumentLabelHeight
```

세 항 모두 고정 px이 아니다 — **실측 + 화면 비례(8~24 클램프) + 실측**.

`50`을 박지 않고 `onLayout`으로 잰 이유는 **`minHeight`가 높이가 아니라 하한**이기 때문이다.
칩의 내용 높이는 `패딩 8×2 + 줄높이 22 + 테두리 2×2 = 42`라 평소에는 `minHeight` 50이
이기지만, 글꼴 배율이 커져 내용이 50을 넘으면 50은 더 이상 "제 높이"가 아니다.

- `Math.round`로 눌러 **서브픽셀 진동**을 없앤다. 실측이 `49.99998` ↔ `50.00002`로 흔들리면
  React의 같은 값 중단이 걸리지 않아 `onLayout` → 리렌더 → `onLayout`이 **실제로 돈다**
- `setState`는 함수 꼴로 불러 이전 값과 비교. 같으면 갱신하지 않는다는 뜻을 호출부에 남기려는 것
  (React가 알아서 멈추기는 한다 — 아래 「바로잡은 설명」 참조)
- 초기값을 `minHeight`와 같게 두어 첫 프레임이 안 튀게 했고, 두 곳이 어긋나지 않도록
  **`INSTRUMENT_LABEL_MIN_HEIGHT` 하나**를 양쪽에서 본다

### 4. 바로잡은 설명 (문서에 반영)

작업 중 "명시적 비교가 무한 루프를 막는다"고 설명했는데 **정확하지 않다.**
React는 `Object.is`로 같은 값이면 스스로 멈춘다 — 같은 파일 363행의 `setHeaderHeight`가
비교 없이도 잘 도는 이유가 이것이다. **실질적인 방어선은 `Math.round`**이고,
명시적 비교는 의도를 호출부에 남기는 몫이다. `doc/실측-레이아웃-onLayout.md` 6절에 정정해 적었다.

### 되돌리면 안 되는 것 (세션 29)

- **오버레이 위치를 스타일시트로 되돌리지 말 것.** `top/left/right/bottom` 중
  하나라도 스타일시트에 박으면 그 변만 인셋을 다시 안 보게 된다. 네 변은

### 되돌리면 안 되는 것 (세션 32)

**반드시 위 주소를 함께 준다.** "저번에 만든 그 페이지 고쳐줘"라고만 하면

주소가 바뀌면 이미 공유한 링크가 옛 내용을 가리킨 채로 남는다.

주소를 잃어버렸으면 터미널에서 **`/artifacts`** — 만든 페이지 목록이 나온다
(`o` 열기, `c` 링크 복사). 직전 세션 것은 **`ctrl+]`**로도 열린다.
웹에서는 `claude.ai/code/artifacts`.

### 원문과 페이지는 따로 논다

페이지를 고쳐도 `doc/*.md`는 안 바뀌고, md를 고쳐도 페이지는 안 바뀐다.
**둘 다 최신이어야 하면 둘 다 고치라고 말해야 한다.**
