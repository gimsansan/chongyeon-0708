## 화면 부위를 부르는 이름 (세션 38에 사용자가 정했다)

**대화에서는 이 이름을 쓴다.** 괄호가 코드 이름이다.

### flashcards 화면 (`app/(tabs)/flashcards/index.tsx`)

```
┌─────────────────────────────────────┐
│              배경                    │  class_R.webp
│  [ 🃏 단어 카드 ] [✓ N 개 익힘]      │  제목 · 익힘배지
│  ──●────────────  1 / N             │  진행바 + 진행숫자
│     ┌─────────────────────┐         │
│     │      카드박스        │         │  ← topCard / topCardBackground
│     └─────────────────────┘         │
│     [◀]   [학습완료]   [▶]          │  카드네비 (앱 탭바와 다름)
├─────────────────────────────────────┤
│         앱 하단 탭바                 │  app/(tabs)/_layout.tsx
└─────────────────────────────────────┘
```

| 이름 | 화면에 보이는 것 | 코드 |
|---|---|---|
| **제목** | `albums` 아이콘 + 「단어 카드」 (세션 39 전에는 `📖  단어 카드`) | `headerTitlePill` |
| **익힘배지** | `checkmark-circle` 아이콘 + 「N 개 익힘」 (세션 39 전에는 `✅`) | `completedBadge` (배경은 SVG `CompletedBadgeBg`) |
| **진행바** | 가로줄 + 눈금 + 마커 | `progressContainer` |
| **진행숫자** | `1 / N` | `progressTextPill` |
| **카드박스** | 카드를 감싸는 사각형 | 크기·위치는 `topCard`, 배경·테두리는 `topCardBackground` |
| **카드박스 오버레이** | 사진 위 베이지 반투명 판 | `cardOverlay` |
| **카드네비** | ◀ 학습완료 ▶ | `bottomNavigationContainer` |
| **앱 탭바** | 맨 아래 탭 아이콘 | `_layout.tsx` Tabs |
| **익힘모달** | 익힘배지를 누르면 나오는 **완료 카드 목록** | `showCompletedModal` → `modalOverlay` > `modalContent` > `modalHeader`·`modalBody` |
| **완료화면** | 카드를 다 익혔을 때 (카드박스 **안**에 들어간다) | `completionContainer` |

```
┌──────────── 카드박스 ────────────┐
│   ┌──────┐   VS   ┌──────┐       │  단어1 / 단어2
│   │단어1 │        │단어2 │       │

### 헷갈리기 쉬운 것 — **익힘모달 ≠ 미션모달**

`modalContent`는 **판 스타일 이름이지 화면이 아니다.** 두 파일에 같은 키가 있고
**StyleSheet가 파일마다 따로라 이름만 같다.** 한쪽을 고쳐도 다른 쪽은 그대로다.

| | **익힘모달** | **미션모달** |
|---|---|---|
| 파일 | `app/(tabs)/flashcards/index.tsx` | **`components/MissionProgressIcon.tsx`** (`components/game/`가 아니다) |
| 여는 것 | 익힘배지 | 미션아이콘 (게임·악기 화면 우상단) |
| 스위치 | `showCompletedModal` | `modalVisible` |
| 모양 | 아래서 올라오는 노란 시트 (`backgroundStar` `#FFF9E6`) | 가운데 흰 박스 |

> **「`modalContent`를 고쳐 달라」는 말은 어느 화면인지 알 수 없다.**
> 화면을 말할 때는 **익힘모달 / 미션모달**, 판만 가리킬 때 `modalContent`.

**특히 자주 걸린 것 넷** — 이것만은 여기에도 적어 둔다.

- **`shadow*` 네 속성과 `Platform.OS === 'ios'`를 새로 넣지 말 것** (`CLAUDE.md` 규칙 4).
  이 앱은 안드로이드 전용이다. 그림자는 **`elevation`으로만** 낸다.
- **흰 바탕에 초록 글자는 `COLORS.successOnWhite`.** `COLORS.success`는 2.2:1이라
  `constants/colors.ts:43`이 이미 금지해 뒀는데 **두 번 어겼다** (세션 40 · 41).
  배경·테두리는 `success` 그대로다.
- **바닥에 붙는 것에는 `insets.bottom`을 렌더에서 인라인으로 더한다.**
  StyleSheet는 인셋을 모른다. 스타일에 고정값을 두면 인라인 값에 덮이거나 제스처바에 물린다.
- **`Touchable`로 무언가를 감쌀 때 그 자식이 삼켜지지 않는지 볼 것.**
  `TouchableOpacity`·`Pressable`은 `accessible`을 끄지 않는 한 켜져 있고
  (RN 0.86 `TouchableOpacity.js:303`), **켜진 요소의 자식은 한 덩어리로 묶인다.**

## 세션 45 주의사항

- **끊긴 세션을 이을 때는 커밋부터 본다.** 세션 44는 「문서 갱신 중」에 끊긴 것으로 보였지만
  코드도 문서 내용도 이미 다 있었고 **남은 것은 `git commit` 하나**였다.
  터미널 출력만 보고 「하다 만 작업」으로 단정하면 같은 수정을 두 번 한다.
- **작업 트리의 삭제(D)를 「사고」로 보지 않는다.** 세션 44·45에 걸쳐 두 번 물었는데
  둘 다 **사용자가 의도한 것**이었다. 물을 것은 「지웠느냐」가 아니라
  **「참조가 남아 빌드가 깨지느냐」**다 — 그건 `Grep` 한 번이면 끝난다.
- **`await` 앞의 상태 전환은 화면을 바꾼다 (세션 44 주의사항과 같은 자리).**
  세션 44에 `matchGameAI`에서 고쳤던 그 결함이 **`matchGame`에도 그대로 있다**(27건 표의 1번).
  짝이 넷(`matchGame`·`matchGameAI`·`matchGamePG`·`orderGame`)인데
  **제대로 가른 것은 PG와 orderGame 둘뿐**이다.
- **로딩 UI가 죽어 있으면 「스타일이 안 쓰인다」가 아니라 「분기가 안 온다」다.**
  1번은 죽은 스타일 3개로 먼저 보였지만 원인은 `setIsGameStarted`의 위치였다.
  **죽은 코드를 찾으면 지우기 전에 왜 안 불리는지부터 본다** (점검표 5절).
- **점검 결과를 인계문에 통째로 옮긴 것은 세션 45가 처음이다.** 27건을 고르기만 하고
  새 창으로 넘어가기 때문이다. 다음 창은 **다시 훑지 말고 이 표에서 골라 고친다** —
  다시 훑으면 줄 번호가 같아도 **사용자가 이미 「그대로」로 고른 14·17을 또 묻게 된다.**
