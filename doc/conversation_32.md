| 레이아웃 | 값 |
|---|---|

**`components/game/InteractiveDrumSet.tsx`** — `drumSetContainer`에 적용:

```tsx
const bottomAlignShift = drumSetSize * (activeLayout.bottomAlignOffset ?? 0);
...
<View style={[styles.drumSetContainer,
  { width: drumSetSize, height: drumSetSize, transform: [{ translateY: bottomAlignShift }] }]}>
```

### 설계 판단 두 가지 (주석으로도 남김)

**1. padding/margin이 아니라 `transform`을 쓴 이유 — 규칙 3**

이 컨테이너는 ScrollView 안에 있고, `scrollContent`가 `flex: 1 + justifyContent: 'center'`입니다. 콘텐츠가 화면에 들어가면 **가운데 정렬**, 넘치면 **위 정렬**로 동작이 갈립니다. padding으로 내리면 콘텐츠 높이가 함께 늘어 정렬 기준이 흔들리고, 실제 내려가는 양이 **가운데 정렬일 땐 지정값의 절반, 위 정렬일 땐 전부**가 됩니다. 즉 작은 폰과 태블릿이 서로 다르게 움직입니다. `transform`은 레이아웃을 건드리지 않아 어느 기기에서든 정확히 지정한 만큼만 내려갑니다.

**2. 잘림 위험 없음 — 확인했습니다**

세션 30이 겪은 잘림이 반복될지 따져봤습니다. 이동 후 **보이는 그림의 아래 끝은 정확히 이동 전 사각형의 바닥 모서리**에 놓입니다(`squareTop + S + gap·S − gap·S`). 즉 3악기 그림이 이미 차지하던 선을 넘지 않습니다. 사각형 박스의 하단 일부가 컨테이너 밖으로 나가지만 그 부분은 **전부 투명 픽셀**이라, 설령 잘려도 화면에 보이는 차이가 없습니다. 그래서 `overflow` 방어 코드를 넣지 않았습니다.

**같이 움직이는 것** — 베이스 이미지, 하이라이트 14장, 악기 마커, 캐릭터가 모두 `drumSetContainer` 자식이라 한 덩어리로 이동합니다. 컨테이너 내부 좌표계는 그대로라 `details` 좌표도 히트 판정도 손대지 않았습니다. 부모의 ◀/▶ 버튼은 하단 고정이라 원래대로 안 움직입니다.


**근거** — 이 세로 위치의 기준은 원래 드럼 그림이 아니라 **순환 버튼**입니다(기존 주석: `버튼과 세로 중앙 맞춤`). 그런데 지금 화면에 실제로 보이는 ◀/▶ 버튼은 부모가 화면 하단에 고정으로 그리는 것이라 세트가 내려가도 **안 따라 내려갑니다.** 캐릭터만 세트를 따라가서 버튼 줄에서 벗어난 것이고, 여백이 제일 큰 2악기에서 48px로 가장 크게 티가 났습니다.

반대로 **악기로 스냅할 때의 좌표는 보정을 그대로 둡니다.** 그건 그림 기준이라, 컨테이너가 내려간 만큼 캐릭터도 같이 내려가야 드럼 위에 정확히 앉습니다. 초기 위치만 화면 기준, 스냅 위치는 그림 기준 — 이 구분을 주석으로 남겼습니다.

### 짚어둘 점 — 4·5악기 캐릭터도 함께 올라갑니다

말씀은 "2악기 캐릭터만"이었는데, 원인이 악기 수별 특수 사정이 아니라 **모든 페이지에 같이 걸린 규칙**이라 한 줄로 처리했습니다. 결과:

| 페이지 | 캐릭터 이동 |
|---|---|
| 2악기 | **48px 위로** ← 지적하신 것 |
| 4악기 | 21px 위로 |
| 5악기 | 19px 위로 |
| 3악기 | 0 (보정 자체가 0) |

이러면 네 페이지 캐릭터가 **모두 같은 높이**가 됩니다 — 이번 세션 변경 이전의 위치 그대로이고, 그 위치는 원래 문제 없던 상태입니다. 4·5는 20px 남짓이라 눈에 안 띄었을 뿐 같은 이유로 어긋나 있었습니다.

만약 4·5는 지금 자리가 더 좋아서 건드리지 않길 원하시면, 보정 적용을 2악기에만 거는 것도 한 줄이면 됩니다. 다만 그건 특수 케이스라 위 규칙보다 설명이 약합니다.

기기에서 네 페이지 다 확인해보시고, 이대로면 커밋하겠습니다. 커밋 메시지는 이번 세션 두 변경(바닥선 정렬 + 캐릭터 보정 제외)을 한 커밋으로 묶을지 나눌지도 알려주세요.

악기 레이블을 제 높이만큼 아래로 내렸습니다. `npx tsc --noEmit` 새 오류 0건 (남은 1건은 무관한 기존 오류).

### 바꾼 것 — `app/(tabs)/drum/index.tsx` 한 파일

```tsx
{ top: headerHeight + instrumentLabelGap + instrumentLabelHeight }
```

`instrumentLabelHeight`가 내리는 양이고, 값은 칩의 **실측 높이**입니다.

**왜 그냥 50을 안 더했나** — 스타일의 `minHeight: 50`이 평소 높이는 맞지만, 기기 글꼴 배율이 크면 칩이 그보다 커집니다. 그러면 "제 높이만큼"이 어긋나죠. 그래서 칩에 `onLayout`을 달아 실제 높이를 받아 씁니다 (규칙 3).

```tsx
onLayout={(event) => {
  const measured = Math.round(event.nativeEvent.layout.height);
  setInstrumentLabelHeight((prev) => (prev === measured ? prev : measured));
}}
```

같은 값이면 `setState`를 부르지 않습니다 — `onLayout → 리렌더 → onLayout` 반복을 막는 자리입니다.

**첫 프레임 튐 방지** — 초기값을 `INSTRUMENT_LABEL_MIN_HEIGHT = 50`으로 두어 실측이 오기 전에도 자리가 맞습니다. 그리고 그 상수를 스타일의 `minHeight`에도 그대로 물려서, 한쪽만 고쳐 둘이 어긋나는 일이 없게 했습니다.

레이블은 여전히 `pointerEvents="none"`이라, 내려온 자리가 드럼 세트와 겹쳐도 터치는 그대로 통과합니다.

기기에서 확인해보시고 — 한 칸이 더 필요한지, 아니면 이 정도가 맞는지 알려주세요. 커밋은 아직 하지 않았습니다.

### 한 가지 바로잡아 적은 것

6절에서 제 설명을 정정해 적었습니다. 제가 커밋 전에 "무한 루프를 막는 자리"라고 했는데, 정확히는 **명시적 비교가 없어도 무한 루프는 나지 않습니다.** React가 `Object.is`로 같은 값이면 스스로 멈추기 때문입니다 — 같은 파일 363행의 `setHeaderHeight`가 비교 없이도 잘 도는 이유죠.

진짜 위험은 실측이 `49.99998` → `50.00002`처럼 **소수점 끝자리만 흔들릴 때**입니다. 그건 매번 다른 값이라 React의 자동 중단이 안 걸립니다. 그래서 **실질적인 방어선은 `Math.round`** 이고, 명시적 비교는 "같으면 갱신 안 한다"는 의도를 호출부에 남기는 역할입니다. 문서에는 이 셋을 나눠 적었습니다.

11절에는 이 저장소에 이미 있는 같은 패턴 세 곳(헤더 높이 363행, 트랙 폭 1013행, 컨테이너 폭 1172·1187행)을 짚어, 새로 만든 방식이 아니라 기존 관행이라는 걸 알 수 있게 했습니다.
