**한 일**

인계문이 적어둔 `bottom: insets.bottom + bottomPanelHeight`만 넣는 대신, **네 변 전부를 제어반과 같은 프레임에 맞췄습니다.**

```js
const overlayFrameStyle = {
  ...safeAreaFrameStyle,
  bottom: insets.bottom + bottomPanelHeight,
};
```

`safeAreaFrameStyle`은 `midgroundLayer`(제어반이 들어 있는 레이어)가 쓰는 바로 그 프레임입니다. 오버레이는 그 형제라 인셋을 못 받는 게 문제였으니, 같은 프레임을 깔고 거기서 제어반 높이만큼만 더 띄우면 둘이 같은 좌표를 봅니다.

스타일시트의 `top: 0 / left: 0 / right: 0`은 뺐습니다. 이제 위치는 전부 렌더 한 곳에서 나옵니다.

**bottom만 고치지 않은 이유**

두 화면은 **가로모드**입니다. 가로모드에서 큰 인셋은 `insets.bottom`이 아니라 **`insets.left`/`right`**(노치·제스처 영역)입니다. `bottom`만 고쳤다면:

- 낙하 카운트다운 숫자가 노치 쪽으로 **`insets.left / 2`만큼 옆으로 밀린 채** 남습니다 — 연주 영역 한가운데가 아닙니다
- 미션 성공 오버레이도 인셋 바깥 여백까지 덮습니다

즉 인셋이 실제로 어긋나는 축을 그대로 두게 됩니다. 같은 결함의 같은 원인이라 함께 고쳤습니다.

인셋이 전부 0인 기기에서는 **이전과 픽셀 단위로 동일**합니다. 세션 28 실기기 확인이 그 조건이었으니 회귀 위험은 없습니다.
