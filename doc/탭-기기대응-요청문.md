# 탭별 기기 크기 대응 요청문 (2026-08-17)

다른 탭에도 기타 탭과 같은 수준의 화면 크기 대응을 시킬 때 **그대로 복사해서 쓰는 요청문**이다.
탭 하나에 한 번씩 쓴다. `[탭]` 자리에 탭 이름만 바꿔 넣으면 된다.

기준이 되는 작업: **「기타 좌측 패널 세로 배치」** = `doc/기타탭-UI개선.md` 6항 · 6-1항.

탭 이름은 이렇게 부르면 된다 (`app/(tabs)/_layout.tsx` 기준):

| 부를 이름 | 라우트 | 탭바 아이콘 | 비고 |
|---|---|---|---|
| 드럼 | `drum` | 음표 | |
| 듣기 | `learn` | 헤드폰 | |
| 단어(플래시카드) | `flashcards` | 책 | |
| 피아노 | `activity` | 피아노 | **탭바를 숨긴다**(`display:'none'`) → 세로 여유가 다르다 |
| 기타 | `guitar` | 기타 | 이미 완료 |
| 동물 | `new` | 발바닥 | |
| 냉장고 | `refri-test` | 눈꽃 | |

## 전체 요청문 (복사용)

```
[탭] 탭, 기기 크기 대응 점검해줘. 기준은 기타 탭에 한 「기타 좌측 패널 세로 배치」
(doc/기타탭-UI개선.md 6항)와 같은 방식이다.

1. 고치기 전에 계산부터 해서 보고해.
   - 이 탭이 실제로 쓸 수 있는 화면 크기. 하단 탭바(64 + insets.bottom)를 쓰는 탭인지,
     화면 방향이 가로인지 세로인지 포함해서.
   - 화면 안 요소들의 고정비 합(패딩·글자·버튼 높이). 그 합이 가용치를 넘는지.
   - 넘는다면 어느 요소가 밖으로 밀려 잘리는지.

2. 그다음 고쳐.
   - 늘고 주는 칸을 하나만 정해서 flex: 1 + minHeight: 0을 주고, 나머지는 flexShrink: 0
     (RN 기본값)으로 둬. 세로가 모자라면 그 칸이 먼저 줄고 중요한 칸은 남게.
   - marginTop:'auto'처럼 "남는 공간"에 기대는 배치는 쓰지 마. 공간이 없으면 0으로 접혀서
     그 요소가 화면 밖으로 밀려 잘린다. 기타 탭 피드백이 안 보이던 원인이 이거였다.
   - 작은 기기: onLayout으로 실제 높이를 재서 임계값 미만일 때만 압축 모드(여백·글자 축소)를
     켜. windowHeight에서 탭바 높이를 빼서 추정하지 마 — 다른 파일의 상수를 베껴 두게 된다.
   - 큰 기기(태블릿): maxHeight/maxWidth로 요소가 과하게 커지지 않게 막아.

3. 지킬 것.
   - 로직은 건드리지 마. 소리 재생·정답 판정·진행도 저장·syncData·화면 방향 잠금 그대로.
   - 색·모양도 바꾸지 마. 세로/가로 치수와 flex만 손대.
   - 내가 쓰는 기기(가로일 때 세로 약 393dp, 2280×1080)에서는 화면이 지금과 똑같아야 해.
     압축은 그보다 작은 기기에서만 켜져야 한다.

4. 끝나면 보고해.
   - 320 / 360 / 375 / 393 / 800dp 기기별로 어떻게 되는지 표로.
   - npx tsc --noEmit 결과.
   - 근거를 doc/에 기록.
```

## 짧은 요청문

이미 위 기준을 아는 세션에서 쓴다.

```
[탭] 탭도 「기타 좌측 패널 세로 배치」와 같은 기준으로 기기 크기 대응해줘.
계산 먼저 보고하고, 내 기기(393dp)에서는 화면이 안 변해야 해.
```

## 고치지 말고 진단만 시킬 때

```
[탭] 탭, 기기 크기별로 잘리는 요소가 있는지 계산해서 보고만 해. 고치지는 마. 이해?
```

끝에 붙인 **"이해?"** 가 실행 금지 신호다(`CLAUDE.md` 규칙 1). 진단 결과를 보고 나서
위의 전체 요청문으로 실제 수정을 시키면 된다.

## 요청문이 이 항목들을 담고 있는 이유

기타 탭에서 실제로 문제가 됐거나, 문제가 될 뻔한 것들이다.

| 요청문 항목 | 없으면 생기는 일 |
|---|---|
| "계산부터 보고해" | 증상만 보고 상태·조건부 렌더링을 의심하게 된다. 기타 탭 피드백은 상태가 아니라 **높이 초과로 잘린** 것이었다. |
| "늘고 주는 칸 하나만" | 여러 칸이 같이 줄면 어디가 잘릴지 예측이 안 된다. 하나로 몰아야 나머지가 보장된다. |
| "marginTop:'auto' 쓰지 마" | 남는 공간이 없을 때 auto 마진은 0으로 접힌다. 화면이 넉넉한 기기에서만 멀쩡해 보인다. |
| "onLayout으로 재라" | `windowHeight − 탭바`로 추정하면 `app/(tabs)/_layout.tsx`의 탭바 높이(64 + insets.bottom)를 각 화면에 베끼게 되고, 피아노처럼 탭바를 숨기는 탭에서 틀린다. |
| "큰 기기 상한" | flex로 늘리기만 하면 태블릿에서 버튼만 거대해진다. |
| "내 기기에서는 안 변해야" | 이미 확인한 화면이 매번 달라지면 검증을 다시 해야 한다. 압축은 임계값 아래에서만 켜지게. |
| "기기별 표로 보고" | "대응했다"는 말만으로는 어느 크기까지 되는지 알 수 없다. 안 되는 구간을 숫자로 남겨야 한다. |
