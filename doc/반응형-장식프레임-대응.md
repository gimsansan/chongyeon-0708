# 장식 프레임 안의 반응형 대응

피아노 하단 바에서 곡 슬롯 SVG와 우측 콘솔 SVG를 맞출 때 쓴 방식이다. 기기마다 따로 디자인하지 않고, **한 규칙으로 우물에 넣고 크기만 자른다.**

적용 위치: `screens/MusicTrainingScreen.tsx`, 프레임은 `assets/icons/pan_res.svg`, `assets/icons/console_res.svg`.

---

## 한 줄

프레임은 칸을 채우게 늘리고, 버튼은 늘어난 우물 비율 안에 두며, 글자·패딩은 우물 크기 공식 하나에 최솟값·최댓값을 건다.

---

## 이 방식이 하는 일

기종 목록(S24, 탭 A8, …)을 만들지 않는다. 화면이 바뀌면 칸 크기가 바뀌고, 칸이 바뀌면 같은 비율이 따라간다.

층은 넷이다.

1. **무엇을 묶을지**  
   같이 보이고 같이 사라지는 조작만 한 프레임에 넣는다. 점수처럼 역할이 다른 것은 빼 둔다.
2. **프레임은 늘린다**  
   SVG를 `preserveAspectRatio="none"`으로 칸에 맞춘다. 곡 슬롯과 콘솔처럼 비율이 다르면 파일을 복사하지 않고 그 칸용 SVG를 쓴다.
3. **내용은 우물에 붙인다**  
   고정 px 여백은 쓰지 않는다. 카본 우물이 viewBox에서 차지하는 비율을 `top` / `bottom` / `left` / `right` 퍼센트로 옮긴다. React Native에서 `padding` 퍼센트는 세로도 너비 기준이라, 세로 맞춤에는 쓰지 않는다.
4. **글자·패딩은 공식 + 클램프**  
   세로는 우물 높이, 가로는 우물 너비에 비례하고 `min` / `max`로 자른다. 작은 폰에서 넘치지 않고, 태블릿에서만 가로 패딩이 조금 늘어난다. 바 높이가 고정이면 글자 변화는 작다.

콘솔 숫자 예 (`MusicTrainingScreen.tsx`의 `consoleContent`, `consoleFit`):

- 우물 인셋: 세로 19%, 가로 4.5% (카본 우물 + 둥근 모서리)
- 글자: 우물 높이 × 0.22~0.24, 12~17px로 자름
- 가로 패딩: 우물 너비 × 0.032, 6~18px로 자름

`onLayout`으로 매 프레임 재측정하지 않는다. `usableWidth`로 칸을 추정한다.

---

## 언제 쓰나

아래가 **동시에** 맞을 때.

- 장식 프레임(SVG·이미지) 위에 실제 버튼·텍스트를 올린다
- 가로는 기기마다 크게 달라지고, 세로 바 높이는 거의 고정이거나 몇 단뿐이다
- Android 가로 화면처럼 **한 줄 툴바**다
- “모든 기기에 픽셀 퍼펙트”가 아니라 **우물에 남고, 极端에서만 덜 깨지면** 된다
- 프레임과 조작의 생명주기가 같다 (같이 보이고 같이 숨는다)

이 화면에 해당한 이유: 하단 바 110px 고정, 콘솔은 준비 화면에만 보임, 토글과 `연주 시작`/`훈련 모드`가 같이 움직임.

---

## 언제 쓰지 않나

- 스크롤되는 목록, 세로 폼, 여러 줄이 줄바꿈되는 레이아웃
- 프레임 없이 그냥 버튼 줄인 경우 → flex + `minWidth: 0`이면 충분하다
- 바 높이까지 기기마다 크게 달라 글자를 높이 비례로 키워야 하는 경우 → 그때는 높이 공식의 이득이 커진다. 지금은 높이 고정이라 가로 패딩 쪽이 본체다
- 버튼 라벨이 프레임 PNG에 그려져 있는 경우 → 늘리면 글자가 깨진다. 프레임은 빈 우물만
- iOS 전용 속성으로 맞추려는 경우 (이 프로젝트는 Android)

## 요청 요령

한 번에 “반응형으로 예쁘게”만 하면 대상이 흔들린다. 아래 순서로 짧게 정해 주면 구현이 맞다.

### 1. 대상을 잠근다

파일과 줄, 묶을 것 / 빼 둘 것을 말한다.

예: `@screens/MusicTrainingScreen.tsx (1290-1363) 스케일·템포랑 연주 시작만 우측 콘솔로. 점수는 그대로. 이해?`

`이해?`로 끝나면 수정하지 않고 대상만 되묻는다.

### 2. 레이아웃을 먼저, 그림은 나중에

합칠지 나눌지, SVG를 쓸지 View로 금테만 맞출지를 먼저 고른다. 이미지 프롬프트는 그다음이다.

예: `우측만 한 콘솔로 합쳐. 같은 SVG 복제는 말고 전용 프레임. 프롬프트 문 작성해.`

프롬프트에 넣을 것: 비율(이 콘솔은 4.3:1), 빈 우물, 글자·버튼 그리지 말 것, 기존 프레임과 같은 금속·금테.

### 3. 유지할 것과 한계를 말한다

예: `파란 버튼색 유지. 그리드 말고 스케일 한 줄·템포 한 줄. 모든 기기 퍼펙트는 아니고 적당히.`

안 말하면 색·배치까지 바꿀 수 있다.

### 4. “우물에 넣기”와 “크기 스케일”을 나눈다

둘은 다른 수정이다.

- 우물에 넣기: 퍼센트 인셋. 겹침·떠 있음 고침
- 크기 스케일: `consoleFit` 같은 공식. 태블릿에서 가로로 조금 커짐

예: `객체들이 우물에 안 맞아. 퍼센트로 맞춰. 그다음 기종 목록 없이 공식으로 패딩만 스케일해.`

### 5. 짧게 확인할 때

끝에 `간`을 붙이면 한두 문장으로 답한다. 구현은 `적용해줘` / `수정해줘`처럼 실행 말이 있을 때 한다.

### 피하면 좋은 말

| 말 | 왜 |
| --- | --- |
| 모든 기기 대응해 | 기종 분기로 읽힌다. `한 공식 + 클램프`라고 적어 달라 |
| 똑같이 만들어 | 곡 슬롯 SVG를 콘솔에 복사하게 된다. 비율이 다르면 전용 프레임이라고 한다 |
| 반응형으로 | 줄바꿈인지, 우물 인셋인지, 폰트 스케일인지 갈린다 |

---

## 구현 시 기억할 것

- Android만. iOS 전용 속성은 쓰지 않는다
- 성능: 퍼센트 인셋과 `usableWidth` 추정은 가볍다. 칸 크기를 state에 넣는 `onLayout`은 회전마다 다시 그린다
- 프레임 `id`는 `panMetal` / `conMetal`처럼 화면에서 안 겹치게 한다
- 훈련 중처럼 프레임 안이 텅 비면, 빈 프레임을 남기지 말고 숨긴다
