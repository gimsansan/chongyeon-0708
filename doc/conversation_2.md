## 4. Claude

드럼 코드 경로를 다시 훑었습니다. 실기기에서 확인할 것은 다음 6가지입니다.

### 1. 첫 터치 지연 (프리로드가 실제로 먹었나)

드럼 탭에 **들어가자마자 1초 안에** 캐릭터를 악기로 드래그.
- 기대: 첫 소리도 두 번째 소리와 같은 속도로 남
- 실패하면: `createAudioPlayer`의 디코딩이 비동기라 `preloadSounds`(`app/(tabs)/drum/index.tsx:147`) 직후엔 아직 준비가 안 된 것 → 프리로드 후 무음 1회 재생 같은 워밍업이 필요

탭을 나갔다 다시 들어와서도 첫 터치가 즉시 나는지 (플레이어 상주 확인).

### 2. ↻ 다시 듣기 연타 — 이번 변경의 핵심 리스크

퀴즈모드에서 ↻를 **빠르게 3~4번 연타**.
- 기대: 매번 처음부터 다시, 겹치지 않고, 소리가 끊기지 않음
- 의심 지점: `context/AudioManager.tsx:78-79`에서 `seekTo(0)`가 Promise인데 `await` 없이 바로 `play()`를 부릅니다. 안드로이드에서 seek 완료 전에 play가 시작되면 **이전 위치에서 잠깐 나다가 튀거나, 첫 몇 ms가 잘려** 들릴 수 있습니다. 여기서 문제가 보이면 `seekTo` 후 재생 or `player.pause()` 선행 등으로 순서를 바꿔야 합니다.

### 3. 서로 다른 악기 동시 발음

캐릭터를 빠르게 다른 악기로 연달아 이동 (킥 → 스네어 → 하이햇).
- 기대: 각자 플레이어를 쓰므로 앞 소리가 끊기지 않고 자연스럽게 겹침
- 끊긴다면 상주 플레이어가 키별로 안 만들어지고 있는 것

### 4. 퀴즈 문제 재생 ↔ 정답 터치음 충돌

문제 소리(`drum/index.tsx:267`)와 정답 제출 시 터치음(`InteractiveDrumSet.tsx:361`)이 **같은 플레이어**를 씁니다.
문제 소리가 아직 울리는 중에 정답을 누르면 그 소리가 끊기고 처음부터 다시 납니다. 실기기에서 이게 부자연스럽게 들리는지 판단해 주세요 (설계상 의도이긴 하나 체감 확인 필요).

### 5. 탭 이탈 시 소리 처리 — 코드상 구멍

`setCurrentTab`을 호출하는 화면이 **드럼뿐**입니다 (다른 탭은 아무도 안 부름). 그래서 드럼에서 소리가 나는 중에 다른 탭으로 나가도 `stopAllSounds()`가 호출되지 않습니다. `drum/index.tsx:161`의 "AudioManager에서 자동으로 정리됨" 주석은 지금 사실이 아닙니다.

- 확인: 소리 재생 중 다른 탭으로 즉시 이동 → 소리가 이어서 나는지
- 샘플이 1초 내외라 실사용에선 안 거슬릴 수 있습니다. 거슬리면 `useFocusEffect` 클린업에서 `stopAllSounds()`를 부르면 됩니다.

### 6. 오디오 세션 (마운트 1회 설정의 부작용)

세션을 `AudioManagerProvider` 마운트 시 한 번만 설정합니다(`AudioManager.tsx:47-53`). 인터럽션 후 복구되는지 확인:

- 드럼 탭에서 **전화/알람**을 받았다 끊고 → 소리 나는지
- 앱을 **백그라운드로 보냈다 복귀** → 소리 나는지
- **다른 앱 음악 재생 중** 드럼 소리가 같이 나는지 (`mixWithOthers` 확인)
- iOS면 **무음 스위치 ON** 상태에서 소리 나는지 (`playsInSilentMode`)
- 단어/동물게임 탭을 먼저 들렀다가 드럼으로 오면 그쪽이 `duckOthers`로 세션을 덮어쓰므로 드럼 소리가 작아지지 않는지 (→ 4번 작업 근거)

## 28. Claude

앞의 CD 비유를 이어가면 이렇습니다.

### 1. 캐시 = "CD를 꽂아 둔 플레이어 8대"

단어 음성 파일은 36개입니다. 매번 CD를 케이스에서 꺼내 넣는 대신, **최근에 들은 8장은 플레이어에 꽂아 둔 채로** 둡니다. 다시 들으려면 재생 버튼만 누르면 됩니다.

### 2. 그 플레이어 8대를 어디에 두느냐

이게 "훅 안 vs 모듈 단위" 얘기입니다.

**훅 안에 두면 = 각 방 안의 선반**

🎧 learn 탭과 📖 flashcards 탭이 각각 다른 방이라고 보시면 됩니다.

- 방을 나가면 **관리인이 선반을 통째로 치웁니다.** 다시 들어오면 빈 선반부터 시작 — CD를 처음부터 다시 꽂아야 합니다.
- 두 방이 **같은 CD를 듣는데도** 선반을 따로 씁니다. learn 방에서 "바다"를 들어놨어도, flashcards 방에 가면 거기 선반엔 없어서 또 꺼내야 합니다.

**모듈 단위에 두면 = 복도의 공용 선반**

- 방을 나가도 선반은 그대로 있습니다. 다시 들어오면 아까 꽂아둔 CD가 그대로 있습니다.
- 두 방이 **같은 선반을 씁니다.** learn에서 들은 단어를 flashcards에서 만나면 이미 꽂혀 있습니다.

그래서 복도(모듈 단위)에 뒀습니다.

### 3. 대신 치르는 대가

복도 선반은 아무도 안 치웁니다. 앱을 켜 둔 동안 **CD 8장이 계속 꽂혀 있습니다.**

다만 단어 파일은 36개 전부 합쳐도 2.7MB라, 8장이면 1MB가 안 됩니다. 요즘 폰 기준으로는 신경 쓸 크기가 아니라서 이 대가를 택했습니다.

### 4. 자리가 다 찼을 때 — "가장 오래 안 들은 CD를 뺀다"

LRU(Least Recently Used)가 이겁니다. 자리는 8개뿐이니, 9번째 단어를 들으려면 한 장을 빼야 합니다.

> **규칙: 가장 오래 손대지 않은 CD부터 뺀다.**

방금 들은 CD는 또 들을 가능성이 높고, 한참 전에 듣고 안 건드린 CD는 당분간 안 들을 가능성이 높으니까요.

**단, 지금 돌아가고 있는 CD는 건너뜁니다.**

이게 `if (player.playing) continue;` 한 줄입니다. 만약 이 규칙이 없으면 — 소리가 나오는 도중에 그 CD를 빼버려서 **재생 중이던 단어가 뚝 끊기는** 일이 생깁니다. 그래서 재생 중인 것은 넘기고 그다음으로 오래된 것을 뺍니다.

---

정리하면:

| | 비유 | 실제 |
|---|---|---|
| 플레이어 8대 | CD를 꽂아 둔 채 대기 | `playerCache` (`CACHE_LIMIT = 8`) |
| 복도 공용 선반 | 방을 나가도 유지, 두 방이 공유 | 모듈 단위 `Map` |
| 오래된 CD 빼기 | 가장 오래 안 들은 것부터 | LRU 축출 |
| 돌아가는 CD는 건드리지 않기 | 재생 중 끊김 방지 | `if (player.playing) continue` |

## 36. Claude

이건 **번역기 함수**입니다. 옛날 라이브러리 말투를 새 라이브러리 말투로 바꿔주는 역할만 합니다.

### 왜 번역이 필요한가

이 앱은 원래 `expo-av`라는 오디오 라이브러리를 쓰다가 `expo-audio`로 갈아탔습니다. 그런데 두 라이브러리가 **같은 것을 다른 이름으로** 부릅니다.

| | 옛날 (`expo-av`) | 지금 (`expo-audio`) |
|---|---|---|
| 다른 앱 소리 줄이기 | `shouldDuckAndroid: true` | `interruptionMode: 'duckOthers'` |
| 다른 앱 소리와 섞기 | `shouldDuckAndroid: false` | `interruptionMode: 'mixWithOthers'` |

옛날 방식으로 쓰여 있는 화면 코드(`matchGame`, `orderGame` 등)를 전부 고치는 대신, **가운데에 번역기를 하나 두고** 옛말이 들어오면 새말로 바꿔서 넘기기로 한 겁니다. `services/audioCompat.ts` 파일 전체가 그 번역기이고, 이 함수는 그중 한 항목을 담당합니다.

### 한 줄씩

```ts
function toInterruptionMode(shouldDuckAndroid?: boolean): InterruptionMode | undefined {
```
"`shouldDuckAndroid`(옛말)를 받아서 `InterruptionMode`(새말)로 바꿔주는 함수"

- `?` = **안 줘도 된다**는 표시
- `| undefined` = 돌려줄 값이 없을 수도 있다

```ts
  if (shouldDuckAndroid == null) return undefined;
```
"**아무것도 안 줬으면, 아무것도 안 돌려준다**"

이게 중요합니다. `undefined`를 돌려주면 expo-audio는 **"이 항목은 건드리지 말라는 뜻이구나"** 하고 기존 설정을 그대로 둡니다. 값을 안 준 것과 `false`를 준 것을 구별하기 위한 줄입니다.

```ts
  return shouldDuckAndroid ? 'duckOthers' : 'mixWithOthers';
```
"**`true`면 `'duckOthers'`, `false`면 `'mixWithOthers'`**"

`A ? B : C`는 "A가 참이면 B, 아니면 C"라는 뜻의 짧은 if문입니다. 풀어 쓰면:

```ts
if (shouldDuckAndroid === true) return 'duckOthers';
else return 'mixWithOthers';
```

### 정리하면 경우가 셋뿐입니다

| 화면이 넘긴 값 | 이 함수가 돌려주는 값 | 실제 동작 |
|---|---|---|
| `true` | `'duckOthers'` | 다른 앱 소리를 **줄이고** 우리 소리를 냄 |
| `false` | `'mixWithOthers'` | 다른 앱 소리와 **섞어서** 냄 |
| 아무것도 안 줌 | `undefined` | **건드리지 않음** (기존 설정 유지) |

### 이 함수 자체는 문제가 없습니다

번역만 정확히 하고 있습니다. 제가 4번에서 문제 삼는 건 **번역기가 아니라 원문**입니다.

`matchGame.tsx:91`이 `shouldDuckAndroid: true`라고 말했으니, 번역기는 성실하게 `'duckOthers'`로 옮겼을 뿐입니다. "동물게임이 정말 다른 앱 소리를 줄이길 원했는가"가 제가 여쭙는 부분이고, 이 함수와는 무관합니다.

> 참고로 `services/audioCompat.ts`는 마이그레이션 잔재라, 새로 쓰는 코드는 이 번역기를 거치지 않고 `expo-audio`를 직접 쓰는 게 낫습니다. 3번에서 `useWordAudioPlayer`를 그렇게 바꿨습니다.

## 44. Claude

핵심부터 말씀드리면 — **동물게임의 훈련 내용은 하나도 안 바뀝니다.**

### 안 바뀌는 것 (중요)

동물 소리 3마리가 **겹쳐서 나는 건 그대로**입니다.

`doNotMix`는 **우리 앱과 다른 앱 사이**의 규칙이지, 우리 앱 안의 소리끼리는 아무 상관이 없습니다. 같은 앱에서 나오는 소리는 이 설정과 무관하게 항상 함께 납니다.

2번에서 제가 망가뜨렸던 그 부분은 안전합니다.

### 바뀌는 것 3가지

#### ① 바깥 앱 소리: "작아짐" → "꺼짐"

사용자가 유튜브를 틀어놓고 동물게임을 켠 상황입니다.

| | 지금 (`duckOthers`) | 바뀐 뒤 (`doNotMix`) |
|---|---|---|
| 유튜브 소리 | 볼륨이 줄어들지만 **계속 들림** | **멈춤** |
| 동물 소리 | 유튜브 소리에 섞여서 들림 | 혼자 깨끗하게 들림 |

겹친 소리를 분해해야 하는 훈련인데 유튜브 소리까지 섞이면 훈련이 안 됩니다. 그래서 이게 개선입니다.

#### ② 게임 시작이 조금 빨라짐

지금은 **게임 시작 버튼을 누른 뒤에** 오디오 설정을 바꿉니다.

```tsx
// matchGame.tsx:89 — 시작 버튼을 누르면 이게 먼저 실행됨
await Audio.setAudioModeAsync({ shouldDuckAndroid: true, ... });
```

`await`가 붙어 있어서 **이 작업이 끝날 때까지 다음으로 못 넘어갑니다.** OS가 오디오 장치를 재구성하는 시간이 시작 버튼과 소리 사이에 그대로 들어갑니다.

앱 시작 시 한 번만 설정하도록 바꾸면 이 두 줄이 통째로 사라집니다.

#### ③ 게임을 나가도 설정이 남는 문제가 사라짐

지금은 동물게임을 한 번 하면 **앱 전체가 `duckOthers` 상태로 남습니다.** 게임을 나갈 때 되돌리는 코드가 없습니다. 그래서 다른 탭들이 각자 자기 설정을 다시 하는 코드를 갖고 있고, 제가 3번에서 단어 훅에 그 복구 코드를 남겨둔 것도 이 때문입니다.

앱 시작 시 한 번만 설정하면 **바꾸는 사람이 없으니 되돌릴 일도 없습니다.** 각 화면의 복구 코드도 전부 지울 수 있습니다.

### 한 가지 확인이 필요한 부작용

`doNotMix`는 **다른 앱 소리를 멈추고, 우리 앱이 소리를 그만 내도 자동으로 다시 틀어주지 않습니다.** (OS와 상대 앱에 따라 다릅니다)

즉 사용자가 음악을 듣다가 이 앱을 켜면, 앱을 끄고 나서 음악을 직접 다시 틀어야 할 수 있습니다.

훈련 앱이니 이게 맞는 동작이라고 보지만, **실기기에서 한 번 확인해볼 항목**입니다. 4-B 작업 때 확인 목록에 넣겠습니다.

---

정리하면, 동물게임 입장에서는 **잃는 것 없이 세 가지를 얻습니다** — 바깥 소리 차단, 시작 지연 감소, 설정이 남는 문제 해소. 훈련 내용(겹치는 소리)은 그대로입니다.

## 46. Claude

인계문에 적었습니다. `handoff.md`의 4-B 절 안에 두 부분을 추가했습니다.

### 1. `doNotMix`가 각 화면에 미치는 영향 (표)

가장 먼저 **"앱 안의 소리끼리는 영향 없음 — 동물게임의 겹치는 소리는 그대로 유지"**를 못박아 뒀습니다. 다음 세션이 이 작업을 하면서 2번과 같은 실수를 하지 않도록요.

### 2. 4-B 실기기 확인 항목 6개 (⚠️ 부작용 포함)

말씀하신 부작용은 **2번 항목**입니다.

> ⚠️ 앱을 끄거나 백그라운드로 보낸 뒤, **멈췄던 바깥 음악이 자동으로 다시 재생되는지.**
> `doNotMix`는 다른 앱 소리를 중단시키고 자동 복구를 보장하지 않습니다 (OS·상대 앱에 따라 다름).
> 사용자가 음악을 직접 다시 틀어야 한다면, 훈련 앱으로서 감수할지 판단이 필요합니다.

여기에 **대안까지 함께 적었습니다** — 감수할 수 없다면 앱 시작 시가 아니라 훈련 재생 직전에만 `doNotMix`로 올리고 화면을 벗어날 때 되돌리는 방식이 있습니다. 다만 그러면 지금 없애려는 지연이 다시 붙으므로 최후 수단이라고 명시했습니다.

나머지 5개는: 바깥 음악이 실제로 멈추는지 / 전화·알람 후 복귀 / **화면별 설정 6곳을 지운 뒤 모든 탭에서 소리가 나는지 전수 확인** / 동물게임의 겹침 유지 / iOS 무음 스위치.

4번(전수 확인)을 넣은 이유는, 4-B가 여러 화면의 코드를 동시에 지우는 작업이라 한 곳만 놓쳐도 그 탭만 조용해질 수 있기 때문입니다.
