`$ARGUMENTS`를 [`doc/점검표.md`](../../doc/점검표.md)로 **전수 점검**한다.
경로가 비어 있으면 [`doc/점검-이력.md`](../../doc/점검-이력.md)의 **「다음 점검 후보」**를 제안하고 멈춘다.

**대상은 파일이 아니라 화면이다.** 이력의 화면 묶음(`import`를 따라간 것)을 보고
딸린 파일까지 범위에 넣는다 — `flashcards`를 훑으라는 말은 `WordFlashcard`·`Waveform`도 뜻한다.

## 순서

0. **다시 훑어야 하는지 먼저 판정한다.** 이력의 「점검 커밋」과 대본다.

   ```
   git diff --name-only <점검 커밋> HEAD -- <파일>
   git status --short -- <파일>
   ```

   **둘 다 비면 그 뒤로 안 바뀐 것이다 — 훑지 말고 그렇게 보고한다.**
   커밋 칸이 `?`거나 비어 있으면 모르는 것이므로 훑는다.

1. **`doc/점검표.md`의 0절(오검 목록)과 0-2절(보류)을 먼저 읽는다.**
   **양쪽 다 지적하지 않는다** — 0절은 그대로 두기로 정한 것, 0-2절은 아직 안 고른 것이다
2. 대상 파일을 **전부** 읽는다. **동작 절(6종류)을 먼저**, 이어서 일곱 갈래를 순서대로 돌린다
   (동작: await 앞 set* · 채점 빗장 · 클로저로 더하기 · 타이머 · 출제/시각 · 닫는 창)
   (1~7: 기준 틀린 값 · 대비 · 접근성 · RN 골격 · 죽은 것/이름 충돌 · 플랫폼 규칙 · 반응형)
3. 점검표에 적힌 `grep` 묶음을 실제로 돌린다. **눈으로 읽고 단정하지 않는다** —
   한글·이모지가 섞인 문자열은 `od -c`로 바이트를 본다
4. 발견마다 **파일:줄 · 무엇이 · 어떻게 되는가 · 근거**를 적는다

## 지켜야 할 것

- **코드를 고치지 않는다.** 이 명령은 보고서만 낸다. 고칠 것은 사용자가 고른다
- **확실한 것과 추측을 나눈다.** 실기기라야 아는 것도, 근거를 모르는 값도
  지우지 말고 **표의 「갈래」 칸**으로 가른다 (아래 「보고 형식」)
- 없는 문제를 만들지 않는다. **0건이면 0건이라고 말한다**

## 보고 형식 — **표 하나**로 낸다

**설명 문단을 붙이지 않는다.** 사용자는 표를 읽고 **번호만 고른다.**

```
## <화면 이름> 점검 — N건

| # | 갈래 | 자리 | 무엇이 / 어떻게 되는가 |
|---|---|---|---|
| 1 | 🔧 | `파일:줄` | … |
| 2 | 📱 | `파일:줄` | … |
| 3 | ❓ | `파일:줄` | … |

(0절·0-2절에 있는 것과 통과한 것은 **맨 아래 한 줄**로. 표에 안 넣는다)
```

| 갈래 | 뜻 | 골랐을 때 |
|---|---|---|
| 🔧 **코드** | 코드만으로 끝난다. **계산으로 확정된 대비도 여기다** | 바로 고친다 |
| 📱 **기기** | 실기기라야 아는 것 — 렌더링·겹침·인셋·소리·체감·태블릿 | 기기 생길 때 **묶어서** 본다 |
| ❓ **확인** | 근거를 모르는 값. 손으로 맞춘 것일 수 있다 (세션 36 `* 0.4`) | 사용자가 답한다 |

> **계산으로 끝난 것은 📱가 아니라 🔧다.** 대비비는 기기 없이 확정된다 —
> 📱로 미루면 값싼 것만 고르는 동안 **진짜 결함이 0-2절에 눌러앉는다**
> (세션 43의 금색 `#FFD700` **1.29:1**이 그 자리에 있다).

### 고르는 법 — 한 줄

```
1, 1-2 고침 / 2, 3 나중에 / 5 그대로
```

**안 적은 번호는 「나중에」다.** 「없음」·「전부 나중에」도 한 줄이면 된다.
**과정을 다시 설명하지 않아도 된다.**

### 다시 묻지 않는 것

**이미 0-2절(보류)에 있는 것은 표에 올리지 않는다.** 물을 것은
**이번 파일에서 새로 나온 것**뿐이다. 0-2절을 비우는 일은
실기기 확인 때 **📱 줄을 묶어서** 따로 한다.

## 끝난 뒤 — 세 가지를 남긴다

1. **`doc/점검-이력.md`의 해당 줄을 갱신**한다 —
   마지막 점검 세션 · 범위 · **점검 커밋** · 접근성 수치.
   **커밋을 빼먹으면 다음에 또 훑는다.** 아직 커밋 전이면 코드를 먼저 커밋하고
   그 해시를 적는다 (세션 41이 그렇게 했다: 코드 `db54615` → 문서).
2. 이력 아래 **세션 노트를 쌓는다.** 표는 갱신이라 이전 결과가 사라진다
3. **고르지 않은 발견을 셋으로 나눈다.** 「나중에」만 반복하면 0-2절이 목록으로만 길어진다.

   | 사용자가 | 어디로 |
   |---|---|
   | 아무 말 없었다 (기본) | **0-2절**. 「왜 보류」 칸에 **📱 기기 대기**인지 **안 골랐다**인지 적는다 |
   | 「그대로」라고 했다 | **0절**. 이유와 정한 때를 적는다 |
   | 고쳤다 | 어디에도 안 올린다. 근거는 커밋과 세션 노트가 갖는다 |

   **안 올리면 다음 점검이 같은 것을 또 보고한다.**

## 고친 뒤에는 다시 훑는다

사용자가 고를 것을 골라 고쳤으면 **같은 화면을 한 번 더 돌린다** (`CLAUDE.md` 규칙 5).
큰 것을 걷어내면 그 아래가 보인다 — 세션 41에서 7건을 고친 뒤 **4건이 더 나왔고,
넷 다 원래 있던 것**이었다.

**재점검은 한 번뿐이다.** 거기서 나온 것은 **고치지 않고 0-2절(보류)에 올린다** —
안 그러면 고침 → 점검 → 또 나옴이 끝나지 않는다.

> **이 명령은 사용자가 직접 부르는 것이다.** 「이해?」가 붙은 메시지에서 자동으로 도는
> 규칙 5와 다르다 — 규칙 5는 「이해?」에서 **아예 돌지 않는다** (`CLAUDE.md` 규칙 5).
